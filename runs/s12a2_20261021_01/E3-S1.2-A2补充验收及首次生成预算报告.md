## 4. 设计和门控评价器

新增 CheckpointEvaluator，通过真实 Worker 执行 Operator、被选程序及修复程序，预期输出只留在宿主。已实现以下检查路径：

## 5. 实际生成配置与预算

实际 HTTP 适配器为 `FlowEvo/src/failure_evo/model_api.py`，无需 SDK；准备请求不会联网。`first_request.preview.json` 固定首个归纳请求，`generation_config.json` 固定配置和哈希。

配置：DeepSeek 官方 `/chat/completions`，请求模型 `deepseek-flash`；本轮查询官方文档所列版本为 `DeepSeek-V4.1-Flash-1017`。实际返回 model/system_fingerprint 尚未知，因为未发起请求，不能把文档版本当成已实测服务版本。[官方模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)

- 生成器使用非思考模式：thinking=disabled，reasoning_effort=none，预期推理 Token 为 0；实际 usage（含 reasoning_tokens）与原始响应均保留。
- 输入保守上限 65536，输出上限 4096；JSON 格式；temperature=0；非流式；并发 1；无自动重试；HTTP 超时上限 180 秒。
- 单一机制族，最多 7 次：归纳 1、初始候选 3、每候选修订至多 1。适配器拒绝超过首族总调用/Token 上限的预算。
- 归纳输出 specification；候选/修订输出含 repair_operator 的 Python code。缺失、截断或模型漂移不计成功，保留返回与已消费预算。
- 只从 DEEPSEEK_API_KEY 环境变量读取凭据，不把凭据写入 Prompt、日志或容器。
- 实际请求必须有绑定 Run ID、协议哈希、货币上限的明确支出授权，以及 BoundedCompiler 已持久化的预留。

请求字段与思考模式依据 [官方 Chat API](https://api-docs.deepseek.com/api/create-chat-completion/) 和 [Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)；本轮仅调整 Operator 生成器配置，不修改原 FlowEvo 求解模型参数。
