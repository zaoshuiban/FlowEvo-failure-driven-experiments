# E2 执行补充协议（首次 API 调用之前）

E1 已审查 93 题。只有两个最终程序被确证为实现失败：taco_0291、lcb_atcoder_abc399_e，均为达到输出上限后产生的截断代码；没有确证算法选择/状态转移错误的最终程序。因此本轮 E2 是 **2 个代码完整性失败的探索性配对试验**，不能作为算法推理失败或错误类别误译的主因果试验。

R0 的反馈均为含“编译错误”的宽泛类别，R1 将其收窄为编译错误；不是已证实的互相矛盾错误类别对照。两题单列“宽泛反馈→具体类别”的辅助队列，真正算法失败上的错误类别纠正主队列为空。旧、新语义完全相同的主队列负对照样本数也为零，不将宽泛类别冒充完全相同。

原设计中“检查点必须曾实际发送过修复请求”是实现方增加的限制，用户的研究要求是冻结历史失败检查点。此次采用已保存的最终失败程序作为共同起点；在历史修复请求模板中替换候选代码和反馈，并固定其余题意、技能上下文和模型参数。R0 是从真实历史最终失败状态继续一次修复，**不是声称重放了原来的完整请求**。原请求和新请求均留存哈希。此调整在任何 E2 响应产生之前记录，不按恢复结果选样本。

每题 R0/R1/R2 各 2 次，每次一次调用，共计划 12 次，上限仍为用户批准的 72 次、300 万新增 Token。R2 仅给题面生成的小输入和独立可算答案，以及公开编译检查所得语法错误，不使用 E1 隐藏输入。两题按固定随机种子安排调用顺序。

所有分组共用首次调用之前冻结的合法隐藏测试集合。taco_0291 用独立线性期望 oracle 重算合法测试参考值，隔离不合法或页数奇偶说明不充分的输入；lcb_atcoder_abc399_e 核验长度/字母范围，并用独立字符映射图 oracle 检查参考。oracle 先与小规模穷举核对。记录剔除和修正数量、全部哈希。评分器调整不是某臂独有，且不根据修复输出调整。

报告分别说明：原 v2 判定和本轮审计判定；完整性修复率及 Token 成本；真正算法恢复/错误反馈因果作用仍无合格样本，不能据辅助试验推断。若实际模型变化或预算不足，停止后续调用并报告实际执行规模。
