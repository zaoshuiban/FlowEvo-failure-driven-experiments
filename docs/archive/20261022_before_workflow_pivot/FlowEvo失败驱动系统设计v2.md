## 1. 目标与研究假设

保留“生成—可信—路由”框架及算子五元组 o=(S,P,V,E,L)。目标从等待稳定终局失败后离线生成专项求解器，改为：在冻结 FlowEvo 的实际执行路径中，在线积累可用失败证据，在题间按预算编译候选，经独立验证后于后续任务介入，降低错误或恢复成本。

不要求失败属于高级算法错误，不要求任务最终失败。交付不完整、局部实现错误、无效修复和已被原生流程修好的中间失败都可研究。普通语法解析、可靠评分、安全执行与正确记账是各组共享基础；其工程收益不能直接当成失败学习的研究增量。

| 假设 | 待检验内容 | 对应证据 |
|---|---|---|
| H1：证据触发生成 | 单可信见证启动候选，比等待多次稳定终局失败更早形成有用制品且构建成本可控 | 首次生成/首次有效复用位置，无效构建及总成本 |
| H2：可执行化增量 | 相同历史知识下，可执行制品优于文本经验或通用恢复 | F 相对 M、G 的配对收益 |
| H3：阶段路由净收益 | 范围和预算约束将局部收益转化为未来任务流收益 | 触发、拒绝、误伤、可靠性与摊销成本 |

以上是假设。历史 G=F 小试验、单个已修复缺陷以及固定响应回放均不证明这些假设成立。

## 2. 当前事实与可用范围

已有 E3-S0 的 800 题、2,132 候选与 8 条独立流作为历史探索材料复用，不为统计数量重新全审计。v1 引用的 1,644 次旧失败信号和 284 次空/语法错误事件属于既有审计口径，不等于新增可信算法失败。35 题可信集、两个事后验证的实现见证和已看过的 R/G/F 结果统一作为开发背景；E3-S1 的 48 题、224 程序审查及证据包保持冻结。

两类实现缺陷（容量与递归）是开发见证，不自动成为跨题机制。E3-S1 的确证数量与两个既有见证采用不同队列和统计口径，不能相加成独立支持。事后诊断只能在其证据实际可获得之后使用。

本地已有 failure_evo 的公开投影、预算、证据链、受限路由及确定性适配入口；它们不是 v2 学习闭环已实现的证明。实际服务器入口、模型、成功库、评分和配置必须由运行清单及哈希确认，不以官方仓库名或本地适配器代替。

## 3. 将三种门槛分开

| 判定 | 需要什么 | 允许什么 | 不允许推断什么 |
|---|---|---|---|
| 失败事实可信 | 原始产物、合法输入/检查或可独立复核的交付证据 | 纳入对应类型的发现池 | 已知根因、跨题迁移 |
| 值得生成候选 | 一条可信失败、可检验干预目标、有界验证方法及学习预算 | 创建 draft/shadow，设计集筛选 | 已获执行权限 |
| 值得有限试用 | 来源修复有效，基础隔离、契约、边界与不适用验收通过 | nursery + experimental，默认最多 5 次范围匹配机会 | 已证明跨题收益 |
| 值得长期保留 | 实际跨任务复用、独立门控/回归及配对收益 | mature；Active 仍需另行正式准入 | 小样本证明总体安全或泛化 |

删除“必须先 3 题/2 来源组、先过 headroom 才能生成”的全局前置条件。独立题数与来源组仍是迁移证据维度；正式权限所需数量和可靠性界须按冻结策略及样本支持确定。不能把删除生成门槛理解为删除部署门控。

单见证路径用于尽早产生 Shadow。聚合路径按多个独立任务的失败或恢复开销提高编译优先级；相同症状不自动认定相同根因。通用恢复已解决正确性时，仍可研究可靠性约束下的效率，但不能预设专用算子一定值得保留。

## 4. 双循环与发布屏障

任务循环：题初加载失败算子库快照及本臂成功库 → 原生生成/执行/重试 → 记录当前公开事件 → 在固定 Hook 运行获授权算子 → 锁定最终候选 → 外部私有评分。公开经验在题末锁定后进入学习队列，私有评分进入独立评价存储。

学习循环：读取已可用公开证据 → 去重/冷却/预算调度 → 规格归纳 → 有限候选生成 → D_des 筛选 → 冻结候选 → 来源修复及基础实际验收 → 有限新生代未来试用 → 收集复用与成本证据 → 独立 D_gate/D_reg 决定成熟晋级；不合格或无预算则保持 Shadow。

新增或修改的版本不得改变当前题快照。题间发布最早作用于下一题；批次实验固定下一批生效。本题已有获授权版本可在 Hook 介入，刚从本题学出的版本不得反过来用于本题。

默认调度建议：首条高可信证据在题末检查一次，此后每 20 题检查编译队列；没有新证据不重复编译同族。该间隔是待冻结实验参数。编译器和求解器可使用同一模型顺序运行，无需多 Agent；排队、编译和验证耗时全部计账。

成功 Skill 与失败学习使用独立命名空间。成功机制在各臂按相同规则、独立状态正常工作；不通过关闭成功复用制造失败。任务初始种子快照可相同，后续状态不得跨臂共享。

## 5. 事件模型与证据权限

FailureEvidenceStore 保存观察、验证、撤销及来源关系；FailureOperatorRegistry 保存制品、生命周期和权限。事实、根因解释和干预收益分别记录，不能以一个 confidence 数替代。

```yaml
event_id: ...
stream_id: ...
task_id: ...
family_id: ...
provenance_group_id: ...
stage: ...
candidate_sha256: ...
parent_sha256: ...
observation_type: artifact | runtime | functional | evaluator | infrastructure
finish_reason: ...
input_legality_status: verified | unknown | invalid | not_applicable
verifier_status: ...
root_cause_status: unknown | hypothesis | verified
observed_at: ...
validated_at: ...
available_from: ...
visibility: public | private
source_evidence_ids: []
repair_evidence_ids: []
validation_cost: ...
synthetic: false
```

| 证据类型 | 可触发动作 |
|---|---|
| 未核验旧 WA/TLE/异常 | 分诊和排队，不认证算法根因 |
| 空产物、语法不完整、length 且无完整代码 | 交付/工作流恢复候选，不强求数学 oracle |
| 合法公开输入上的实际异常或可信错答 | 局部修复候选；原因未定则限定症状范围 |
| 最小反事实及正反测试 | 支持规格与边界，不单独证明迁移 |
| 未见程序上的有益干预、误触发与回归 | 支持晋级及路由收益判断 |
| 非法输入、评分错误、基础设施故障 | 进入相应工程账本，不直接编译成算法修复规则 |

finish_reason=length 且代码完整时不自动续写或丢弃。没有公开测试时，语法完整只算 structural_pass；空测试绝不产生 public_tests_pass。

visible_at(t) 要求事件已观察、已达到所用证据等级、available_from≤t，且来源依赖当时也可见。编译记录须保存源证据集及哈希。hidden PASS/FAIL 也属私有信息，不得影响重试、停止、成功库准入、失败编译或后续更新。

## 6. 算子规格与宿主契约

五元组沿用原始含义：S 为输入、输出、适用/拒绝边界及资源规格；P 为可执行程序及提示模板；V 为版本、代码哈希和依赖指纹；E 为开发、独立验证、回归和运行证据；L 为生命周期状态。验证方案写入规格和证据协议，不改变 V 的原始含义。

```yaml
operator_id: ...
version: ...
operator_kind: workflow_recovery | code_repair | task_solver | prompt_policy
source_mode: historical_development | chronological_simulation | live_online
artifact_sha256: ...
hook: before_native_retry | before_final_return
input_contract:
  task_public: ...
  candidate_code: ...
  public_feedback: ...
  generation_metadata: ...
  candidate_ledger: ...
  remaining_budget: ...
preconditions: []
allowed_actions: []
max_model_calls: ...
max_tool_calls: ...
max_seconds: ...
decline_conditions: []
postchecks: []
fallback: resume_native_continuation
evidence_ids: []
fingerprint: ...
registry_snapshot_id: ...
```

返回 status=applied/declined/error，可带 candidate_code 或 selected_candidate_id、validation_status=not_checked/structural_pass/public_tests_pass/failed、actual_cost 和 evidence_ids。宿主重新核验返回内容，不能信任算子自报的通过状态、费用或权限。

applied 仅表示执行了允许动作。算子无权修改评分器、隔离权限、总预算、生命周期或库版本。需要资源变化时，只能申请宿主已预设的能力；静态审查不能替代进程隔离。模型和工具调用经宿主代理预留、执行、结算，未知用量保留非零最坏预留，回退不退还消耗。

**首轮可执行能力冻结：** S1.2继续采用S1.1的确定性代码变换/公开账本选择能力，`max_model_calls=0`；算子不能持有密钥或直接联网。生成器可以在独立学习预算内调用模型，这与算子执行时调用模型是两种成本和权限。先验证无内部模型调用的制品能否生成、门控并有增量；仅在研究证据显示能力不足时，另设宿主模型能力代理、额度预留和失败结算协议，经过独立验收再扩展。通用四类operator_kind属于长期设计范围，不表示本轮四类均已支持。

区分 prompt-only、程序变换、工作流恢复和完整 solver。固定 wrapper 外新增提示仍属 prompt-only；单独存在代码生成模块不代表闭环已接入。生成记录至少含请求/响应 ID、实际模型、参数、源证据/规格哈希、制品哈希、修订链与实际成本。人工写出的专用逻辑标为人工工程规则。

## 7. 两个 Hook、候选账本与原生回退

路由输入为任务公开视图、阶段、代码、公开反馈、剩余预算和题初库版本。先查生命周期/授权、证据与指纹，再判断 applicable/inapplicable/unknown，最后按冻结优先级选最多一个算子。无法安全消解冲突时拒绝；不使用未经校准的逐题概率分数。

| Hook | 位置 | 成功或拒绝后的宿主行为 |
|---|---|---|
| before_native_retry | 原生重试/修复前 | 合格干预进入原检查点；拒绝/失败后按剩余预算走同一原生续跑 |
| before_final_return | 原生最终选择和锁定前 | 按预注册公开选择规则处理；拒绝时恢复原生返回策略 |

每个 Hook 到达实例最多尝试一个算子，不递归、不串联、不在拒绝后换第二个试探；到达实例由 task_id、checkpoint_id、hook 唯一标记。全题仍受统一调用/工具/时间上限限制。Hook 不是免费增加模型槽的理由，不另起“通用分析→通用求解”的新基线。

候选在生成或返回后即登记原始源码、哈希、父关系及结构状态，验证失败或缺少测试均不得静默删除。公开验证采用三类宿主结果：

| public_check_outcome | 条件 | 选择行为 |
|---|---|---|
| passed | 非空可信公开测试执行完成并全部通过 | 继续检查范围、预算与选择策略；不代表隐藏正确 |
| failed | 有可信公开测试且观察到不通过 | 保留候选和失败证据，拒绝替换，原生续跑 |
| unavailable | 没有可靠公开测试，或评价器不可用/证据不足 | 保留候选及缺失原因，拒绝替换，原生续跑；不得计作功能失败 |

现有`validation_status`保留；新增正交字段`public_check_outcome`、`tests_run`、`checker_id`、`unavailable_reason`区分测试覆盖和结构状态。`structural_pass`与`unavailable`可并存；评价基础设施错误单独记账，不编译成程序根因。当前实现尚未完整区分这三类，属于下一步迁移要求。S1.2仍不允许仅结构通过就改变程序选择。报告三类数量、比例与独立程序数，并将缺测试导致的未应用与路由未命中分开。

候选账本保留所有原始产物和新制品、父候选、结构状态、公开检查及成本。最近完整候选、最近公开测试通过候选与外部隐藏最优严格区分。前两者只按冻结策略选择；隐藏最优仅离线上界分析。提议验证失败不覆盖先前可用候选，预算耗尽按原生策略返回；不能隐式选择历史隐藏最佳。

关闭插件时两个 Hook 均为空操作；原生请求、节点数、候选选择和返回策略与冻结基线保持一致。若新增候选保留策略，须作为各组共同协议修订另行冻结，不能混在关闭插件的兼容性测试里。

## 8. 生命周期、门控与两条收益路线

代际独立于权限：nursery / mature / cold。新生代准入不要求先证明 Generic 失败或跨题收益；先通过来源修复和基础验收，才获得绑定实验、未来任务及最多 5 次机会的 experimental 权限。源码与范围仍不可变，暂停/冷藏不返还额度。详情与证据格式见代际管理修订。

生命周期：draft → shadow → experimental → active；可 rejected；失效或严重回归则 suspended，再 retired 或新版本重验。晋级由宿主注册表完成，证据追加留痕。

| 状态 | 行为权限 |
|---|---|
| draft/shadow | 离线/影子分析，不改变在线 Prompt、检索、行动、停止或选择 |
| experimental | 仅预注册、显式授权的试验分支；绑定实验 ID、范围和快照 |
| active | 仅在正式准入的源码、模型、基线、评分、依赖、范围和预算内执行 |
| rejected/suspended/retired | 不可调用，保留审计记录 |

晋级路线 A：相同预算下提高可靠完成或减少错误。路线 B：满足预先设定的可靠性约束时降低恢复调用、Token 或延迟。效率算子无需硬性净增两道正确题；便宜地输出错误不能构成效率优势。

首轮小样本最多 experimental。“至少两个独立检查点有成本节省、目标集无观测可靠性下降”可作为 Pilot 继续条件，不是总体非劣证明。active 需要单独冻结可接受损失、效应与样本/不确定性要求，当前不虚设默认阈值。

候选只在 D_des 选优。每族冻结一个版本后，对 D_gate/D_reg 进行一次独立评估；门控失败不能换第二名继续试同一分片。新版本使用新的封存分片，材料耗尽则保持 Shadow。隐藏泄漏、越权、评分篡改或预算突破直接拒绝，不能被综合收益抵消。

## 9. 首批候选与编译预算

首轮最多两族，允许最终零候选或零晋级。

1. 主目标：产物不完整后的恢复选择。公共解析器和结束原因检测为共同基础，研究的是阶段、已有候选和预算条件下如何恢复或拒绝。
2. 第二目标：可达索引域与分配容量不一致。已有阶乘表见证是事后开发证据；需生成有边界的分析、修改和验证，不把所有 n 无条件改成 26。
3. 递归深度为替补目标；不得无限抬高上限或关闭沙箱。迭代恢复必须遵守语义、资源和验证契约。

每族最多一次规格归纳、三个初始候选、每候选一次设计修订：2×(1+3+3)=14 次生成类请求。门控/验证分支另设硬上限，不在 14 次中隐去。候选数、费用、冷却和任务间调度全部进入冻结配置；没有新证据不反复搜索。

## 10. 保持实际运行栈，最小增量迁移

800 题实际路径涉及 benchmark.py 与 CodeSkillLibrary；官方 code_math.runner 和 eval.runner 不是同一执行路径。先记录实际入口及成功经验行为，在其上加插件，不同时换检索器、运行栈或模型推理参数。若原路径使用私有反馈，建立所有组共享的公开反馈适配基线并单独报告协议改变。

| 现有本地组件 | 已有能力 | v2 待做 |
|---|---|---|
| contracts.py | PublicTaskView、PublicFeedback、Fingerprint、OperatorCard | 事件元数据、Hook/动作契约、账本/快照及返回协议 |
| evidence.py | 追加证据链、功能见证认证、3题/2组机制发布及 headroom | 增加独立失败事实通道与单见证编译资格；旧严格机制认证保留作较强声明，不能拦截 Shadow |

## 11. 时序模拟与真正干预的边界

原运行还原：复用 E3-S0 事件、8 流和依赖边，只说明历史发生了什么。原失败库为零不证明新学习器有效或无效。

影子模拟：仅使用模拟时点可得公开信息；新诊断须当时运行或按当时可用确定规则复算并计费。原 8 流各自独立；共享库实验另冻结任务级合并序列，称为新模拟流，不能用并行 mtime 造因果顺序。Warm Start 预载事后见证与空库冷启动分轨。

真实续跑：干预一旦改变程序、Prompt、动作或可见反馈，后续必须从该分支实际生成/执行。仅无干预且完整请求相同才可复用缓存，不能接回历史 l3/l4 充当新策略表现。影子结果只报告积累、编译、门控、触发及潜在覆盖，不报告新系统端到端成功率。

## 12. 指标、费用与停止规则

分别报告事件证据级别/独立题数；候选/真实制品/生命周期；首次生成与首次复用；自然触发、拒绝、误触发、跨族覆盖；完整性、有限测试正确、目标恢复及非目标回归。

统一费用口径时：

```text
NetSaving(N) = Σ[C_B_online(i) − C_F_online(i)]
               − C_induction(N) − C_gate(N) − C_learning_audit(N)
```

F_online 包含检测、路由、算子、剩余原生续跑及回退。模型价格、Token、工具秒数分别列账，价格已知时才转换为同一货币；人工审查未定价记未知，不能记零。实验多臂支出与部署所需成本分开。没有实际配对基线或预注册随机干预，不更新净胜统计。

检查点条件收益、自然流触发频率与摊销成本分开；动态共享状态下不将题目/版本/分支直接当独立样本。优先按独立题流、来源组或顺序重复表达不确定性。

工程通过以透明性、隔离、时序、预算与撤销证据为准。F 相对 G/M 无可复核差异则不扩展该算子；零触发区分机会缺失和路由故障。没有独立门控材料不能晋入 mature；满足来源修复及基础验收时可有限 nursery 试用，否则保持 Shadow。不补造失败，不挪用最终测试。具体分阶段协议以配套计划为准。

## 13. 自动生成与验证闭环的完成标准

在现有 LearningLoop/BoundedCompiler/注册表职责内串联流程，不以更多模块名称代替闭环。每个学习作业必须可追溯地执行以下状态：

```text
eligible_fact → spec_requested → spec_frozen
 → candidate_generated → design_evaluated → [bounded_revision → design_evaluated]
 → winner_frozen → gate_evaluated → regression_evaluated
 → shadow_retained | experimental_authorized
 → published_for_future_task → controlled_execution → measured
```

候选首次生成即为不可执行draft；基本契约和来源检查后进入shadow。规格文本不是Operator制品。实际源码必须能在允许的Worker中加载并履行动作契约；生成失败、空源码、接口不合格、预算不足均记录明确终态。一次规格、三个候选、各一次修订为上限，允许不足或零合格候选。模型失败不自动重试、不转移额度。

每一步记录job_id、family_id、证据/数据分片摘要、输入和输出哈希、实际模型/请求ID、执行状态、耗用预算、时间和后继状态。恢复同一作业时不得重复已消耗请求或门控分片；未知调用结果保守记账，等待宿主明确处理，不能重启后当免费请求。

设计筛选规则在调用前冻结：先契约/权限/范围合格，再按预注册可靠性或效率目标排序，平局用固定规则；只在D_des选一个赢家。修订仅使用D_des反馈。赢家的源码、规格、依赖、模型、范围及动作上限一起冻结后才进入D_gate/D_reg。成熟门控失败不晋级，不回选第二名继续测同一分片；新生代仅保留已授权的剩余额度，发生可信回归则暂停。

至少一条真实公开可信失败应可沿此路径到达实际Shadow源码，且不经过旧MechanismStore三题认证。工程夹具只验证调度，不能替代该端到端证据。只有真实API来源、可执行制品、独立评估和权限记录齐全，才可称自动生成与验证闭环已执行；若无人晋级，应报告闭环运行但未获可用算子，不把它写成在线收益。

进入experimental后的独立检查点须与发现、设计和已消耗门控材料隔离。受控执行验收只证明能正确发布、触发、拒绝和续跑；增量价值需由S2的F−G、F−M支持。F只超过B不足以归因于可执行化。真正在线长期效果仍由未来冷启动顺序流验证。
