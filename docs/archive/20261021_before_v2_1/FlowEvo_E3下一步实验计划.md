# FlowEvo E3 下一步实验计划 v2

修订日期：2026-10-21。状态：待实施、待预注册的实验协议。本次仅修改机制设计与实验计划，新增模型调用为 0；14 次、96 个分支等均为提案上限，不表示已获实验费用授权或已经执行。

配套：[机制设计 v2](FlowEvo失败驱动系统设计v2.md)。旧计划保存在[修订前归档](archive/20261021_before_v2/FlowEvo_E3下一步实验计划.md)。本文的阶段编号替代旧版 S1–S5 推进顺序，不修改历史 E3-S0/S1 的名称、产物或结论。

## 1. 阶段、进入条件和交付

| 阶段 | 研究问题 | 进入条件 | 规模与费用边界 |
|---|---|---|---|
| E3-S1.1 | 最小学习插件是否透明、隔离且预算受控 | 确认实际基线，复用既有材料 | 新增模型 API 为 0；工具成本另记 |
| E3-S1.2 | 一条可信失败能否形成有边界候选并完成影子验证 | S1.1 通过、证据和划分冻结、获得本阶段预算 | 最多两族，最多 14 次生成类调用；验证预算另冻 |
| E3-S2 | 可执行经验是否超过原生、Generic 和文本经验 | 有合格冻结候选及 experimental 授权，独立检查点充足，分支预算获批 | 最多 24 检查点×4 臂=96 分支；不是 96 次 API |
| E3-S3 | 冷启动题流能否积累、编译并在未来复用 | S2 有可信条件收益、独立新题和门控分片可用、预算获批 | 最多 60 题×4 臂=240 任务级执行，3 批各 20 题 |

不再要求先形成 3 道同机制题、2 来源组或先完成旧版 72 次 headroom 试验，才允许生成候选。生成资格和执行准入分开；没有合格候选不能启动 F 干预，不能把空 F 组结果解释为算子无效。

## 2. 基线冻结与数据角色

先形成 baseline_manifest：实际入口及源码哈希、配置/实际模型、生成参数、原生节点/停止/返回规则、评分和公开反馈版本、成功库机制、依赖及平台。记录究竟是完整 FlowEvo 路径还是 FlowEvo-adapted code runner；不能同时换执行栈、检索器或模型再归因于新机制。

各组共享评分修复、I/O、语法检测、结束元数据、安全执行、公开反馈和记账基础。若原路径依赖隐藏 PASS/FAIL，先冻结共同的公开反馈适配基线；把适配的影响单列。最终私有评分仅在源码锁定后由外部评价器运行，不回传重试、选优、成功入库、失败编译或后续更新。

| 数据角色 | 用途 | 隔离要求 |
|---|---|---|
| 历史开发背景 | 已有 800 题、35 题可信集、两个见证、48 题审查及已见 R/G/F 结果 | 已进入分析，不能改 seed 伪装独立确认 |
| D_dis | 提供公开可用发现证据 | 时间可用性、来源与合法性明确 |
| D_des | 有限修订和三候选选优 | 不含门控/最终私有材料 |
| D_gate | 冻结赢家的独立晋级评估 | 与发现/设计来源组隔离，一版本用一次分片 |
| D_reg | 无目标、近似症状、边界和冲突回归 | 不反馈给候选继续修订；失败后不得换第二名重试 |
| S2 检查点 | 开发性条件干预 | 来源题、设计题和近克隆家族之外；不称最终确认集 |
| S3 新题流 | 顺序积累可行性 | 未参与设计，按元数据与可信准入选择；不能预筛模型失败 |

ID/文本去重、来源/翻译/参数变体分组、结构近克隆审查均需记录。参数化探针可增加同一程序覆盖，不能增加独立原题数。私有门控输入仅由评价职责读取，分离不要求多个模型 Agent。若私有门控决策用于晋级，这是独立门控角色；必须与当前任务最终隐藏评分严格分离。

S1.2 的 D_gate/D_reg 失败后，开发侧仅获预定决策与审计摘要；详细反例若开放则该分片转开发材料，后续需新分片。最终测试不得补作门控。

## 3. E3-S1.1：最小插件与透明性验收

复用现有 E3-S0 事件及可信评价组件，不重做 800 题语义认证，不改写历史实现快照。保留原成功 Skill 能力，失败证据与失败制品使用独立存储。

实施范围：公开事件 schema；单见证编译资格；去重/冷却/学习预算队列；制品生命周期；题初库快照及题末/批末发布；before_native_retry 与 before_final_return 两 Hook；宿主预算代理、候选账本和原生续跑。真实生成器仅定义适配契约，本阶段用明确标为 synthetic 的夹具验收。

| 验收项 | 工程探针及通过条件 |
|---|---|
| 插件关闭兼容性 | 固定历史响应下，模型输入、节点数、程序选择及返回规则与实际冻结基线一致 |
| Shadow 零影响 | 加入/改变 Shadow 内容不改变在线请求、检索、行为、停止或候选选择 |
| 时间屏障 | 本题产生的新版本不影响本题；下一题/下一批才进入快照；事后见证不倒填 |
| 隐藏隔离 | 修改隐藏答案、PASS/FAIL、未来修复不改变观察、Prompt、路由或学习决策 |
| 证据触发 | 单条可信交付/功能证据可排入 Shadow；旧 WA、非法输入和工程夹具不冒充根因 |
| 原生回退 | decline/error/超时恢复同一检查点的原生流程，耗用资源保留，原候选不丢失 |
| 预算权限 | 超调用、工具、时间和能力边界由宿主阻止；未知用量非零预留，算子不可自行 active |
| 版本撤销 | 制品/模型/范围/评分/依赖或授权漂移即阻断；suspended 不可执行 |
| 返回验证 | applied 不自动正确；空测试不通过；完整代码即使 length 也不自动重写 |
| 分支与账本 | 原始产物、新候选、父关系和公开选择依据可追溯，无隐藏选优 |

这些是待实现验收要求，已有 55 项单元测试和固定响应回放只能复用其覆盖部分，不能宣称 v2 已通过。人工故障探针不进入自然失败数、机制支持或 F 的学习池。

交付：实际基线清单、最小代码 diff、事件/动作接口、兼容性与权限/预算/时序日志、未覆盖项。进入 S1.2 不以跨题机制数为条件，而以工程安全、证据资格和角色划分为条件。

## 4. E3-S1.2：真实候选生成与时序影子验证

最多两族：主目标为产物不完整后的恢复选择；第二目标为可达索引域与容量不一致，递归深度作为替补。无需凑满两族。语法解析和 length 读取属于所有组共享工具；学习对象为给定阶段/候选/预算时选择恢复动作及拒绝边界。

每族冻结 D_dis、D_des、D_gate 和 D_reg，记录来源组及可用时间。正例优先真实历史故障；负例覆盖完整程序、同症状不同原因及超范围代码。单程序多个参数不是多个独立程序。若材料不足以支持门控，则可生成 Shadow，但不能晋级。

生成类预算：每族最多 1 次规格归纳＋3 个初始候选＋每候选 1 次设计修订，最多 2×(1+3+3)=14 次请求。不转移未耗配额为更多候选。模型失败/未知消耗计账，无免费重试。验证中的模型调用、Token、工具、时间与费用另设硬上限；这些数值未冻结前不执行对应调用。

编译输入只含当时可用公开证据、明确范围和允许动作；保存完整请求/响应、实际 API 模型及生成参数、制品/证据哈希和修订链。不得先人工写好专用算法再称为模型从失败中生成。人工规则可保留为 G 或工程对照。

三候选只在 D_des 筛选，每族选一个赢家并冻结后再做独立门控及回归。失败不拿第二名继续碰同一门控集，新版使用新封存分片。首轮小样本最多 experimental，限定实验 ID；没有独立材料则保持 Shadow。

影子模拟保留 E3-S0 原 8 流独立性。共享库需另冻任务级合并次序，称新模拟流；不使用并行 mtime 形成知识共享顺序。事后容量/递归见证仅作已标记 Warm Start，冷启动需在模拟时点重新获得相应证据。

逐制品报告四个时间点：源证据首次可用、生成开始、验证结束、首次获准使用，并记录学习等待和验证成本。只报告候选形成、门控、触发和潜在覆盖，不把影子回放写成端到端收益。

## 5. E3-S2：最多 24 个真实检查点的 B/G/M/F 干预

按预定次序从发现/设计来源及近克隆家族之外选取；建议 12 个目标失败、6 个无目标错误的完整候选、6 个相似症状或超范围候选。数量不足按实际报告，不注入错误补正例，不根据最终隐藏结果挑样本。

这是开发性挑战集，估计给定检查点的恢复与成本，不估计自然失败率。每个检查点冻结任务、程序、合法公开反馈、剩余预算和成功库快照；四臂从同一状态开始。

| 臂 | 内容 | 回答的问题 |
|---|---|---|
| B | 共同工程修复后的冻结 FlowEvo 原生续跑 | 实际基线 |
| G | B＋从公共规格构建的廉价通用检查/恢复 | 是否普通工程规则已足够 |
| M | B＋与 F 相同证据的文本知识卡 | 是否失败知识仅作为语言经验已足够 |
| F | B＋真实生成、独立门控的可执行算子 | 编译为制品是否有额外价值 |

M/F 在此检查点实验中具有相同历史证据、范围、触发点及相近信息条件；M 以文本进入原生修复，F 运行制品。F 的编译和验证费用单列。G 的工具和 Prompt 在 API 前冻结，至少包括合理语法检查、一次代码优先恢复和公开候选保留；可加入公共规格直接导出的容量/递归通用规则，不故意弱化。

每检查点每臂一次，最多 96 分支，独立单位不是 96 道任务。统一原生续跑总预算，F 增加调用也在同一总上限内，其他臂有相同预算机会但不强迫无用调用。调用次数取决于原生剩余节点和分支动作，不能写成 96 次模型请求；Token/工具/时间/货币硬上限需在运行前估算冻结。

F 一旦改代码、Prompt、动作或反馈，下游需实际生成/执行。仅未干预且完整请求相同可用缓存；禁止拼回原历史 l3/l4。缓存付费成本与逻辑成本分账。

主要比较 F−G、F−M，F−B 为系统参照。逐题报告完整程序恢复、有限公开测试及外部最终正确、误触发、回归、拒绝、调用/Token/延迟；原任务后来成功的检查点恢复不等于新增整题成功。

Pilot 继续依据可为至少两个独立检查点成本节省且目标集无观测可靠性下降，或可复核的可靠性提升；须结合来源独立性及非目标回归判断，不当作非劣统计证明。F 与 G/M 无可复核差异不扩展该族；零触发先核查适用机会和路由。没有合格 F 制品则暂停本阶段并报告原因，不用手写专用算子冒充。

## 6. E3-S3：60 题真实顺序流

仅 S2 出现可信条件增益后启动。60 道未参与设计的新题，建议 TACO/LCB 各 30，按元数据、来源隔离及可信准入冻结，不按模型失败筛选。供给不足在运行前缩减并报告。

3 个连续批次，每批 20 题；B/G/M/F 使用相同任务顺序、模型、资源和成功机制规则，各自状态独立。主轨 F 失败库为空；本批公开证据可在批末生成和独立门控，下一批才可使用。M 同样仅积累本臂当时可见的文本经验，证据准入与更新时间公平；不能从 F 的干预后轨迹免费共享。S2 的 M/F 同证据条件不外推为动态流中的跨臂共享。

第 1 批积累 → 批末学习 → 第 2 批复用与积累 → 批末更新 → 第 3 批复用。第 3 批后形成但无使用机会的制品仍计成本。门控用预封存独立分片，用尽则不晋级，最终私有评分不进入动态状态。

预载历史见证另设 Warm Start 诊断轨，不合并冷启动结果。若运行，题流和预算另行冻结。后续可另设 30 题冻结库测试纯复用，非本轮强制项目。

最多 240 次任务级执行，不等于 240 次模型请求。题数、批次、学习触发、每族候选、生成/验证/API/工具/时间上限和价格版本在开跑前固定。60 题单顺序只作可行性证据；增加独立流/顺序重复须另预注册，不挑最有利顺序报告。

## 7. 指标、成本和推断边界

同时呈现：失败直接证据与独立题数；候选形成和首次未来复用；机会/触发/拒绝/误触发；可靠性与恢复轮数；总成本。

```text
NetSaving(N) = Σ(C_B_online − C_F_online)
               − C_induction − C_gate − C_learning_audit
```

在线项包含检测、路由、算子、原生续跑及回退。生成/门控/失败调用/未知预留单列。Token、工具秒数和不同模型价格不混加；人工成本未定价则记未知，不能写零。实验多臂额外支出与部署成本分别报告。没有配对基线或预注册随机干预，不更新净胜统计。

挑战集条件收益、自然流触发频率、全成本净收益分开。分支、程序版本、同题重复不是独立任务，动态状态下题目也非简单独立同分布；优先按独立流/顺序和来源组表达不确定性。有限测试通过不等于全域正确，空测试不算 PASS。

## 8. 启动前必须冻结的配置

- actual_entrypoint、baseline/model/scorer/dependency/protocol 指纹及实际模型漂移停止规则。
- stream/order、task/family/source split 清单及私有信息访问边界。
- library_snapshot、成功库机制、发布屏障、Hook 与候选选择/返回规则。
- max_families=2、candidates_per_family=3、max_revision=1、归纳每族 1 次；生成类最多 14 次。
- 学习触发/冷却、验证分支预算、调用/Token/工具/墙钟/货币上限、未知用量预留与失败重试规则。
- G/M 冻结内容、D_des 胜者选择、门控分片一次性使用及 experimental 权限。
- 可靠性/效率主终点、可接受损失与 Pilot 继续条件、误伤和未知评分处理。

S1.1 可用零 API 工程夹具推进；其余阶段配置缺项只设计不执行。当前尚未冻结所有费用数值，不把提案上限解释为可直接运行的配置。

## 9. 当前交付与停止条件

当前设计交付为 v2 机制、配套协议和代码迁移差距。下一实施交付应为《失败算子学习器最小实现与首次候选生成报告》，分清零 API 接入结果与预算获批后真实候选生成结果；包含实际基线、diff、schema、双循环状态、成功/失败库隔离、制品来源、门控、权限/预算/时序回归和费用账本。

越权、隐藏泄漏、评分篡改或预算失控即停止并使版本失效；预算或独立门控不足保持 Shadow。F 无增量则不扩展；未触发如实报告机会和路由。无需再等待高级算法终局失败，也不为了方法叙事强求生成或晋级数量大于零。
