## 新规则

```json
{"when":{"candidate_state":"STRUCTURAL_PASS","public_result":"WRONG_ANSWER","remaining_calls_min":1},"action":"REGENERATE_FRESH","fallback":"NATIVE"}
```

候选状态使用真实宿主术语：NO_COMPLETE_CODE、COMPILE_ERROR、STRUCTURAL_PASS。最后一项仅表示语法通过，不能证明完整或正确。条件限于状态、公开结果和剩余调用阈值；没有题号谓词、任意表达式、自定义提示或预算修改能力。重复JSON键、未知字段及额外权限均拒绝。阈值并不预留额外调用额度。

两种动作由相同宿主实现：

1. REPAIR_EXISTING：发送当前源码和已审核公开反馈。
2. REGENERATE_FRESH：发送题面及公开输入/预期，不发送原失败代码、旧模型输出、实际错误输出或调用栈。不附加历史参考解答。

两者采用相同交付要求、模型配置、工具与预算。Generic同样可选两种动作，当前冻结基线为无源码时重新生成、有源码时修复。该基线不是理论最优选择；后续实验必须报告规则与Generic实际是否产生动作差异。

## 生命周期与证据

生成并通过规则契约的制品可保存为nursery/Shadow，不要求先解对来源题。失败来源以引用保留，归档候选不会删除失败证据。已有FailureEvidenceStore继续负责真实证据保存及可信性。

逐测试ID比较要求相同覆盖范围：

- 合法行为：Shadow。
- 有改善且无已知测试退化：LOCAL_IMPROVEMENT，仍为Shadow。
- 来源从失败变为所核对测试全部通过，或同一配对复核双方全部通过且F完整成本更低：VERIFIED_BENEFIT，可申请受限试用。这只是来源范围证据。
- 已观察到测试退化：暂停。两方均失败但F便宜不构成效率收益。未知成本不允许按0处理。

授权还要求宿主基础契约、边界、负例、回退及无已知危害检查通过，并显式指定任务名单、授权标识、最多5次机会。评估报告持久化哈希，在授权和调用时复核。调用前锁定并扣减机会；重启保留状态，同一任务不重复消耗授权；异常保留使用记录，结果不自动换算为节省。

这些管理接口属于可信宿主控制面：证据引用的真实性、报告来源、实际安全检查及授权标识由实验编排方负责，不能将模型输出直接当作这些参数。当前模块不是自动判定研究证据真实性的系统。

旧候选不会自行重新激活。重新学习只产生提案，要求新的证据引用和改变机制假设的说明；须由宿主核查证据确实独立且相关。提案不发送请求、不恢复旧权限、不继承旧预算。

## 新实验的明确接入方式

1. 从FailureEvidenceStore提取当时可见公开材料，使用新Run的学习预算发送器调用 `generate_rule`，持久化所有原始版本和诊断；最多一候选加一次修订。
2. `RuleMemory.add`保存规则和可信证据引用。Shadow可调用纯函数`choose`观察，不可通过任务入口调用模型。
3. 离线来源评价可显式调用`RepairChoiceClient.attempt`；传入同一任务Budget及已验收的隔离公开评价器。程序源码不会在规则解释器内执行。记录来源结果与正反检查，再由宿主调用`record_assessment`和`authorize`。
4. F任务入口使用`run_trial(memory, key, client, task, code, feedback, budget, evaluate)`。G使用`generic_choice`和同一个`client.attempt`。M若加入，应仅使用预注册文本经验，另行冻结公平协议。
5. 结果declined时，调用方恢复原生流程，必须继续使用同一个已扣减Budget；它不意味着停止或节省了原生调用。发送状态未知的异常向上传播，不能自动重试。

模型调用继续使用WorkflowClient/SharedTransport与既有PersistentBudget。最终请求预检先于预算预留；编译和求解分别使用冻结的学习/求解账本。本轮没有修改定价或调用真实API。
