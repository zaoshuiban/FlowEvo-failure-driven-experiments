# FlowEvo 机制修订说明：v1 → v2

日期：2026-10-21。此次修改对象是设计文档与实验协议，不包含源码改动、远程推送、模型调用或新实验成绩。

## 1. 关键决策

| v1 | v2 | 保留的边界 |
|---|---|---|
| 跨题机制认证及 headroom 是生成前置条件 | 单可信见证＋可检验目标＋有界验证即可生成 Shadow | 单见证不证明迁移、不直接授权执行 |
| 产物问题主要归通用工程，研究聚焦局部机制 | 产物恢复、实现缺陷和算法错误均可研究 | 基础检测所有组共享，需比较通用恢复 |
| 稳定失败/修复困难决定继续生成 | 可靠性与恢复效率均可构成研究空间 | 空输出更便宜不是效率收益 |
| 离线形成后部署，在线更新靠后 | 任务循环与题间学习循环同时纳入最小设计 | 题初快照、未来生效，学习成本显式记账 |
| 首版替换 l3 的 proposed 修复 | 两个 Hook、applied/declined/error、宿主验证与原生续跑 | applied 不等于正确，不增加免费槽 |
| 机制与制品认证容易被读作单一门槛 | 失败事实、编译资格、执行权限分开 | 版本、证据、权限和范围均绑定 |
| 旧 G/M/O0/O1 与较长 S1–S5 流程 | 主协议 B/G/M/F，S1.1→S1.2→S2→S3 | 旧消融可另预注册，不能与新主要比较混用 |
| 对跨题新增正确题强调较多 | 可靠性提升或可靠性约束下恢复成本下降 | 小样本最多 experimental，active 另需正式证据 |

五元组保留原义：S 规格，P 程序及提示模板，V 版本/代码哈希/依赖指纹，E 开发/独立验证/回归/运行证据，L 生命周期。

## 2. 代码迁移差距（本轮只核对，不改实现）

核对对象为本资料包 FlowEvo/src/failure_evo，不等同于服务器实际 800 题入口。2026-10-20 对远程 c783927 的冒烟测试通过的是旧实现，不能作为 v2 验收证据。

| 组件/行为 | 现状 | 下一步最小修改 |
|---|---|---|
| PublicTaskView/PublicFeedback | 公共字段投影、隐藏反馈截断已存在 | 扩展 finish_reason 等白名单元数据；空公开测试不签发 PASS |
| EvidenceStore | 哈希链及事件时间过滤 | 加 stream/task/available_from 和来源依赖，按证据等级控制可用性 |
| MechanismStore.certify/publish | 功能见证要求 oracle/反事实；发布要求 3 题/2 来源组 | 保留为严格机制证据，另增 artifact/runtime 等失败事实及单见证编译通道 |
| record_headroom | 依赖机制已发布，检查 3 次 G/D* 的困难与收益 | 作为可选开发诊断，不作为所有 Shadow 生成的入口；补效率证据路线 |
| AdmissionRegistry | FORMAL_ADMISSION 的 ADMIT 和 suspend | 新增 experimental 独立授权、实验 ID、门控分片消耗与正式 active 区分 |
| OperatorCard/Router | active、阶段、AST/关键词、指纹/证据和预算检查 | 显式 Hook、动作范围、冻结优先级、题初快照、受控试验权限 |
| SandboxOperatorRunner | 静态策略、源码快照、输出过滤；隔离由外部 Worker 提供 | 新返回协议、宿主 postcheck、真实成本与能力代理，不信任自报验证 |
| Controller | 五阶段、固定响应可测、保留候选哈希；l3/l4 可加入 proposal | 连接真实原生续跑、两个 Hook、完整候选账本、发布屏障和选择回滚 |
| benchmark_failure_evo.py | 离线夹具入口 | 基线 manifest 与真实入口适配；关闭插件 parity 不仅验证节点骨架 |
| 编译队列/生成器/双循环 | 现有模块未形成这些 v2 端到端能力 | 独立队列、去重冷却、有限生成/修订、设计冻结、学习预算和未来发布 |

旧的 proposed 是提议，不等于新协议 applied；需显式适配并经宿主校验。旧 published_at 时间检查不等于已实现题间发布屏障。现有 PUBLIC_PASS 接受的是评价器声明，空测试语义必须由可信宿主落实并验收。

## 3. 实施顺序

1. 冻结实际入口和共同公开反馈基线；成功经验机制按各臂独立状态保留。
2. 加事件/证据等级、编译队列、注册表权限与题初快照，提供确定性编译夹具。
3. 两 Hook 对接原生续跑、候选账本和宿主预算；通过关闭/Shadow/时序/隐藏/回退验收。
4. 冻结两族输入、D_dis/D_des/D_gate/D_reg、三候选选优及全部学习/验证预算。
5. 获得生成阶段预算后保存真实 API 生成来源，独立门控；具备合格制品再启动 B/G/M/F。

此处是迁移任务清单，不是本轮已执行项。既有 experiments 中的源码快照、证据哈希、结果和机制计数保持原样。
