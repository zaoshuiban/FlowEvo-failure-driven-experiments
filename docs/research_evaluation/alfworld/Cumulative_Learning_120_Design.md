# ALFWorld 失败技能获取与 120 局累积学习实验

**状态：设计修订稿，尚未选定游戏清单、设定费用或授权执行。** 研究问题是：Agent 能否从真实环境交互失败中提出可执行的修正，凭独立环境证据验证它能否跨游戏使用，并通过题间累积改善后续任务表现？

## 1. 原方案需要修复的问题

| 问题 | 研究影响 | 修订 |
| --- | --- | --- |
| 直接进入 120 局连续实验 | 零介入无法区分诊断失败、生成失败、验证不通过或缺少适用机会 | 先做技能获取和证据表示实验，再验收调度和开展主实验 |
| 失败标签、根因和技能混写 | STEP_LIMIT 和动作循环可能由多种原因产生，标签相同会诱导宽泛策略 | 分离观测、假设和经过干预验证的效果，先测局部转移再测跨游戏整局收益 |
| 学习槽位和 Gate 分片一一绑定 | 初期弃权或来源失败就会耗尽全程机会 | 用信息增量、幂等和全 Run 资源账本调度；Gate 资源耗尽单独记账 |
| 只按游戏哈希排重，且把加载器模式当作文件 split | 同场景的衍生游戏可能跨角色；历史评估会被误称为纯 train | 核验真实路径、内容、任务谱系与场景；按角色冻结数据 |
| 120 局边学边评，T/F 与等调用 R 的含义不充分 | 难以区分工作流收益、轨迹信息贡献、算子因果作用和费用差异 | 分开在线和冻结评价，预注册比较和估计对象，用单独的表示消融及后续对照回答窄问题 |

## 2. 基线审计、效力与选题

### 2.1 论文成绩与本地执行入口

论文 v2 报告 GPT-4o-mini 85.6%（三种子均值）及 DeepSeek-V3.1 94.0%。其 ALFWorld 协议是在 134 个标准 out-of-distribution 任务上在线累积成功技能，每局至多 50 步。模型、数据和成功学习路径都需要与本地分别核对。 [FlowEvo 论文 v2，§4.1、表 1 和表 3](https://arxiv.org/html/2607.21596v2#S4)

| 本地证据 | 配置及含义 |
| --- | --- |
| 上一轮失败学习 120 局 | 请求和已归档响应均标识 `deepseek-flash`，禁用 thinking、温度 0、每动作输出上限 1,024 Token、每局最多 50 步。G/F 各 93/120（77.5%）。两组全部 `pure_dynamic`，直接复用和经验注入计数均为 0。两次调用学习器产生一个候选，但没有任何候选介入后续求解。 |
| 更早的原生 120 局 | 91/120（75.8%）端到端，91/111（82.0%）可评价局；20 个完整环境失败，另有 9 个 256 Token 输出截断。题集及交付上限不同，只作参照。 |
| 新 G 的本地强基线 | 未测。必须在同模型、同采样框、成功技能编译/检索/复用已经验收的配置下重新校准。论文数字可作效力敏感性场景。 |

实际失败学习路径为 `run_alfworld_failure_learning.py → LearningStream.run → learning_runtime.execute_episode → PolicyGenerator(AlfWorldGenerator) → AlfWorldExecutor.run`。最后一层支持成功技能入参，但这条调用未传 `skill_library_result`、绑定或经验上下文。题间仅在 F 的可信失败时入库并调度，成功后没有调用成功轨迹编译器。PolicyGenerator 接收的是失败策略 Registry，不能代替成功 SkillLibrary。

仓库另有 `run_20task_validation.py` 的 `full_library` 条件。它在题前调用 `SkillLibrary.retrieve`，向 executor 传模板、示例、insight 和参数绑定，在成功后调用 `AlfWorldCompiler.compile`，写回模板和示例，并记录治理统计。双物体放置当前明确跳过直接绑定/重放，可走示例或 insight 引导。该入口也会从失败聚合 `common_pitfalls`。正式 G/F/R 应共同保留这项原有统计及相同的成功技能机制，F 增加的处理仅为从完整失败轨迹归纳并生成可执行修复策略。另需把成功编译调用接入审计账本，冻结治理/holdout 和恢复规则，按实际运行路径核验。 [本地成功学习入口] [ALFWorld 执行验证]

### 2.2 高基线敏感性与阶段目标

若把各场景的成功率暂视为稳定，90 局失败数的期望为 90 × (1 − p)，且只有完整、可定位、有可重放状态的部分能转化为学习或修复机会：

| 假设成功率 | 90 局预期失败 | 30 局预期失败 | 理论净提升上限 |
| --- | ---: | ---: | ---: |
| 本地历史动态路径 77.5% | 20.3 | 6.8 | 22.5 个百分点 |
| 论文 GPT-4o-mini 85.6% | 13.0 | 4.3 | 14.4 个百分点 |
| 论文 DeepSeek-V3.1 94.0% | 5.4 | 1.8 | 6.0 个百分点 |

94% 的独立同分布近似下，30 局完全没有基础失败的概率约为 15.6%。场景共享、持续学习与失败异质性均会改变分布。双侧精确 McNemar 检验在没有反向败局时至少需要 6 个净胜局才达到 0.05；30 局的这个门槛相当于 20 个百分点。规划示例：若单局 F 独有成功概率为 4%、G 独有成功概率为 1%，净提升为 3 个百分点，按不一致对数的二项分布和条件方向概率精确求和，30 对的检验效力约 0.08%，120 对也只有约 15.2%。这些数字是独立配对假设下的情景推演。正式规划须用校准得到的不一致率、场景数和最小重要效应重算。

因此把 90＋30 定位为**单类机制 Pilot**。主要机制证据来自前置阶段独立新游戏上、在同一检查点主动开关失败技能的配对修复。最后 30 局的 F/G 整体成功率只作描述性效益估计。若需要确认强基线上的几个百分点增益，另行预注册更大的锁库评价和多个独立场景组/任务流。避免用正式流的失败数或显著性扩样。建议先冻结独立校准池（如 24–30 局，单列预算），在目标类型验证 G 的成功率、可重放失效检查点比例、成功技能编译及引导覆盖。若需估计自然不一致率，在其中做预定的重复 G/G 配对。报告宽区间；校准结果只决定是否具备机制研究条件及后续样本量，不按校准局难度选主流题目。

### 2.3 六类机制线索与推荐范围

| 类型 | 历史动态 G 成功 | 机制线索与需验证的问题 |
| --- | ---: | --- |
| 普通拾取放置 | 19/20 | 论文代表运行 14 次无回退直接执行全部成功，成熟复用路径可能只剩少量搜索与找不到对象的恢复机会。 |
| 灯下观察 | 16/20 | 论文代表运行无纯直接执行。物体持有、到灯附近及观察动作的状态配合值得验证，表中未提供这一类的治理 holdout 对照。 |
| 清洗放置 | 15/20 | 论文代表运行直接执行较多。本地候选看见海绵仍反复导航，说明宽泛探索策略无法推进该来源局；应测拾取后清洗状态识别和失败后的恢复。 |
| 加热放置 | 13/20 | 论文代表运行 19/23 局走纯直接路径。操作容器和加热后取回的前提值得检查；较低的动态基线无法证明成功技能难复用。 |
| 冷却放置 | 12/20 | 论文同一治理种子的引导/holdout 为 16/18 对 3/3，样本不足以确认负迁移。可检查容器状态、冷却是否完成及误入重复导航。 |
| 双物体放置 | 18/20 | 论文代表运行无纯直接执行，模板/引导曾因负迁移被压制；另一治理种子中 2/14 对 1/3 是小样本线索。适合验证两个实例的身份绑定、已完成子目标保护，以及只恢复剩余子目标。当前本地动态成功率较高，不能假设有大量失败。 |

论文数字来自不同表的代表运行及治理记录，不能当作本地的因果估计。后三列中的状态和恢复问题是待证伪假设；只有独立前缀重放、策略开关对照和环境反馈能确认修正效果。 [论文附录表 12 与表 16](https://arxiv.org/html/2607.21596v2)

**推荐预注册双物体放置作为单类 Pilot。** 理由是成功技能的直接路由缺口和可观察的中途恢复问题，而非从六类中选择历史成功率最低的类。上一轮动态 G 在该类达 90%，说明此选择未追求较低基线。本地真实 `train/` 的该类为 813 局，已知游戏哈希排除后有 789 局，具备抽样空间。场景、任务组和 Gate 分离后是否能保留 120 局，需再做清单可行性检查。结论只针对该类型。

先写定任务类型、可解性、曝光排除、场景角色及随机种子。随机分配合格场景到角色，再在角色内对游戏按冻结规则随机抽取，记录不同场景组的权重、配额及排除原因。难度、预期收益、目标模型答错或修复表现均不能用于主流或最终集纳入。历史失败只用于明确标记的机制前置实验；若随机冻结后发生缺失，按预先指定的无结果规则处置。若配额或强基线校准不足，记录可行性并在查看任何主流结果前决定是否另立协议；不能测试多个题型后择优报告。

### 3.2 数据角色及冻结规则

| 角色 | 来源及使用方式 |
| --- | --- |
| 技能获取与消融来源 | 历史已结算的真实 ALFWorld 失败轨迹。完整证据及哈希可核验，按游戏和谱系分配给前置开发或消融，保留定位困难的样本。 |
| 在线学习 （90 局，双物体放置） | 从真实 `train/` 抽取。三组同题；三组从当前局已锁定的成功中更新成功技能，只有 F 新增失败策略入库。正式运行从同一空库状态开始，前置实验产出的技能和轨迹不导入。 |
| 策略来源验证 | 前置阶段为历史失败发生的游戏；主实验为已完成的在线来源游戏。可重放来源状态做诊断和修订，结果单列。 |
| 独立 Gate (不计入 120) | 从角色隔离后的 `valid_seen/` 或预先预留的 `train/` 挑选。前置技能获取、消融和主实验使用互不重叠的 Gate 池。每池在候选出现前冻结分层和分配规则。 |
| 最终冻结评价 （30 局，双物体放置） | 使用真实 `train/` 中已独立预留的游戏和场景。90 局结束后锁定成功库、失败库和学习型治理状态，30 局只做同题评价，沿用进入评价时有效的权限，不再生成或调参。运行期暂停/额度耗尽只按冻结的安全规则执行，实际可用次数单列。 |

宿主从 `traj_data.json` 核对 `scene.scene_num`、任务类型与参数、trial 及目录中的任务组。清单至少绑定实际 split、游戏和轨迹文件 SHA、场景 ID、任务组、初始状态指纹及曝光标记。按场景分组先为最终评价留出场景，再在其他组分配在线和 Gate，随机种子、筛选顺序和同组采样上限预注册。单类内交错不同场景组，题序不依赖模型输出。正式冻结前必须合并工程实际执行记录、历史分配清单和可追溯近重复关系；缺失来源单独标记。

最终评价的游戏、任务组和场景均与本轮在线、来源、Gate 及前置实验隔离。优先从历史未分配场景抽取，另外披露与全部历史场景的重叠。主实验 Gate 必须与所验证候选的所有来源分离，并与最终评价隔离。若场景约束下不能满足 90/30 与验证配额，先公布交叉表，再事前决定缩小样本、改配额或另立仅跨游戏的协议。公开 train 上的保留场景只支持本地实验的隔离结论，无法推断模型预训练曝光或官方 unseen 表现。

模型、候选代码和学习器只获得当时可见的任务目标、环境观察、合法动作与已完成的本组允许证据。未来游戏路径、任务 ID、隐藏事实、专家轨迹、PDDL 原文及 Gate 结果保留在宿主；结构化样本也不能旁路这些边界。Gate 的逐题结果不回流生成或修订；本地完整记录仅用于审计。最终 30 局结果在版本锁定前不可访问，也不回流。冷启动与角色隔离通过清单交集、请求投影及时间截断验收。

## 4. 失败轨迹与诊断表示

| 层 | 字段及证据边界 |
| --- | --- |
| 原始轨迹 | 目标、初始公开状态，每步动作前观察和合法动作、提交动作及来源、动作后环境反馈、合法动作变化、步数、done/won、请求/Worker 回执。原文按步保存并绑定不可变哈希。 |
| 局部片段 | 引用原轨迹哈希与步区间，含前置公开状态、关键动作、紧接反馈、之后短段及省略区间。固定规则可提名首次重复、连续无进展、非法或无效动作、明显状态转移附近的片段。一个轨迹可有多个候选，允许定位缺失。 |
| 状态与失败表现 | 区分观测事实和由文本推测的状态。记录显式反馈、动作集合差异、可见状态是否改变及未知值。独立记录动作循环、无进展、步数耗尽、执行错误；终局未成功不作根因标签。 |
| 诊断假设 | 提名的关键步或区间、可能原因、反证、替代解释、置信/未知、可检验预测。模型自报只作为假设。引句必须指向原步记录。 |
| 验证效果 | 宿主记录同检查点的原动作和候选动作、预注册的局部状态变化、整局结果和独立 Gate 配对结果。即使修正有效，根因仍可保持不确定。 |

每份候选声明可观测的触发状态、预计局部效果、拒绝条件、最大干预范围和回退方式。环境宿主从同一初始种子重放公开动作前缀，验证状态/观察/合法动作绑定一致后，比较原动作和候选动作及短段效果。整局来源验证按同游戏、同配置比较原生和候选路径。前缀不可复现或目标状态不可观测记为无法验证。候选可以只执行一个局部动作，其他步骤继续原生求解。单步局部改善、整局来源成功和独立跨游戏通过是三种不同证据。

## 5. 分阶段实验及进入条件

以下是规模和规则草案。每个真实阶段在启动前分别冻结保守总费用、调用和 Worker 单位成本估计、时间及安全界限。

| 阶段 | 假设与做法 | 指标及进入条件 | 资源及终止 |
| --- | --- | --- | --- |
| A 技能获取前置实验 | 先检验真实历史失败能否产生局部修正并跨游戏复用。建议先冻约 12 个独立历史失败游戏，兼顾表现和类别，不按是否看起来可修复挑样。依次定位、提出可证伪根因假设、生成策略、局部重放、来源整局验证、独立 Gate。 | 完整记录无法定位、根因不明、弃权、源码拒绝、不可重放、局部失败、来源未改善和 Gate 拒绝。可行性信号为至少一个真实策略完成全链路，并在主研究题型的独立 Gate 满足预先冻结的规则。零有效技能时仍可继续消融和零 API 工程检查，正式效益试验需要重新论证，不能把可行性算作通过。 | 预算包括历史取证、诊断、源码和工程修订、配对来源与 Gate、Worker。按已冻结病例完成、预算无法预留下一作业或安全停止结束。无需产出固定数量。 |
| B 证据表示消融 | 用与 A 隔离的冻结历史失败，建议约 12 个游戏。相同来源分别给完整轨迹、仅事实摘要、带前后状态和原步引用的局部片段。三个条件同模型、生成契约、求解和验证设置，隔离各自上下文并轮换执行顺序。 | 首要比较完整轨迹与简单事实摘要在同来源上的有效技能产出率、每美元有效产出，隔离可见逐步证据的价值。局部片段为第三条件，检验压缩后能否保留有用状态转移。报告定位可复核率、来源局部改善、整局通过、跨游戏通过和成本。有效完成要求三条件对齐、证据格式完整、盲化裁决和缺失可核算；全部零产出仍是有效消融结果。没有明确优势时沿用预先指定的保守表示，禁止按最终 30 局成绩选择。 | 完整轨迹须原样送达。共同 wire 上限下先冻结三条件都可容纳的子集并报告排除数，单列超长轨迹覆盖和费用。各条件预留同规则的生成、验证资源，真实输入 Token 差异计入费用。摘要/片段提取成本也计入；模型摘要若启用，其调用独立记录。为同来源的三个条件提前锁定候选及分配，再在同一隐藏评估块配对裁决一次，各条件看不到彼此结果。按冻结配对完成或统一资源、安全停止。 |
| C 累积学习功能验收 | 用 Mock 模型、已曝光夹具和真实 ALFWorld/Worker 演练全流程。至少覆盖三次合法学习边界、历史未关联证据重访、生成不通过、通过后实际后续执行、R 额度及消耗。 | 零付费请求；锁定、来源验证、Gate、授权和真实 Worker 路径可重放。相同输入/候选版本不重复发送或验证，预算/验证耗尽、重启及 UNKNOWN 处理通过，G/F/R 均覆盖真实成功编译、持久化、下一局检索及实际使用或拒绝；旧的失败聚合规则在三组一致，新增可执行失败策略只在 F，未来和最终评价信息不可进入学习。Mock 只证明工程行为。 | 冻结本地步骤、Worker 时间和夹具；异常或不一致即修复再验收。 |
| D 单类 120 局 Pilot | 90 局连续学习，30 局锁定库后的评价。估计 F 工作流相对 G 的描述性净收益，并区分实际干预和学习资源开销。 | 进入需 C 通过、A 有真实跨游戏可行性证据、B 已完成并冻结表示选择、独立校准池已验证 G 的实际基线及机会率、数据角色审计通过、预算可覆盖全基础流、Gate 和 R 规则可执行，以及独立授权。进入后无需保证产出、调用或提升。 | 三组 120 局的基础动作请求上界为 18,000 次（每局最多 50 次，按现有每步最多一次原生请求估计），另计三组成功编译、F 学习、来源、Gate、Worker 与 R 额外尝试。先校验最终求解协议是否仍满足该上界。按 120 局完成、不可恢复异常或基础资金/总预算不足结束。 |

**有效技能的计数单位**是事前可追溯的机制/适用域 ID。实质相同的源码改写和父子修订合并，保留全部版本费用。只有候选满足安全和动作接口、来源局部修正成功、来源整局判据通过，并在冻结独立 Gate 达到准入条件，才计一次。前置技能获取的产出率是「至少产出一个有效技能的预注册来源病例 / 全部预注册来源病例」，弃权与无法验证保留在分母；同时报告有效机制数及候选级通过率。消融用同一病例为分母单位。对多来源候选保留病例与机制对应关系，并单列去重计数。

**单位费用有效产出**为去重有效技能数除以完整获取支出。获取成本包括取证或转换、关联与诊断、所有生成/修订、静态检查、来源重放、独立 Gate、Worker 及失败或拒绝的尝试。共享批次费用按冻结规则分摊；无法归属的失败费用仍计入总体分母。分别报本轮可估 API 美元和 Worker 时间，实际账单可得时补列。使用历史轨迹的原始采集成本作为单列的全成本口径，并报告不重复计价的增量口径。正费用、零有效技能时，技能/美元为 0；美元/技能不可估计。试用和后续回退费用另计入运行总成本。

**阶段预算核算草案。** A/B 的病例数用于控制前置实验规模。按 12 个 A 病例和 12 个 B 病例各三种表示，分别预留 12 和 36 个病例条件单元。每单元按一次诊断和一次初始源码生成估算，只有有效提案才预留整套来源与 Gate 执行，另计有依据的修订与摘要提取。若每个候选需验证 1 局来源及 k 局 Gate，整局配对验证最多需要 100 × (1 + k) 次原生动作请求，外加局部重放、Worker 和可能的独立诊断裁决。用实际冻结的 k、模型上下文上界及供应商报价换算保守美元预留。C 的模型预算为 0，环境步骤及 Worker 用本地计时和资源上限。D 以 18,000 次基础请求上界核算预留，再加 R 已承诺额度、三组成功编译、F 学习、验证和工具预算。全 Run 金额是控制边界，以上病例单元或请求上界用于资源估计；D 的学习不会因累计作业数达到一个固定值而停止。

## 6. 学习调度与 Gate

每个非末题边界在三组全部锁定后运行一次调度检查。20 局是统计和 R 额度结转窗口，第 90 局提前结清末个 10 局在线窗口。证据和待处理队列跨窗口持久。整场、窗口都不设学习次数配额。资源约束是共享 Run 费用账本、请求上下文边界、验证容量及 Worker 时间与安全检查。为剩余基础配对和已承诺 R 调用预留保守费用，辅助作业按完整验证路径预检；恢复复用已结算回执，发送状态 UNKNOWN 时阻断新请求并保留预留。

| 动作 | 允许触发的信息增量 |
| --- | --- |
| 关联 | 新锁定的可见证据，包含此前未覆盖的游戏/局部状态、能区分现有解释的转移或明确反例。按新证据锚点召回旧未关联证据与相关簇，优先独立谱系、较少重访的旧证据和反例。完成一次请求只记分析尝试，空结果和弃权保留重访资格。 |
| 生成 | 已有明确可执行的干预、公开可识别的触发状态、可观察的结果和失败边界。共同根因仍疑似时可生成 Shadow。相同终局或重复动作标签只支持检索，不能单独成为可生成判据。 |
| 修订 | 新的可区分反例、新的状态转移证据、可复现来源回放发现或具体接口诊断。仅改变题目措辞、同一现象重复或同候选未通过隐藏 Gate 都不触发重试。工程修订若改语义或源码，建立完整新版本并重新验证。 |

事件记录时间、可见证据 ID、原文与发送投影 SHA、簇版本、候选范围、触发理由、发送前估算、调用/Worker 回执、最终状态和不可发送原因。关联按证据及投影视图、协议版本去重；生成按机制版本、实质新证据和接口身份去重；验证按完整候选版本及数据块绑定。调度优先证伪信息和跨谱系支持，再按入队顺序处理同优先级，防止积压一直让位给新失败。忙或预算暂不可用保留队列，记录截止时未处理量；无新增信息进入等待。

沿用现有来源验证、Gate 阈值与 Registry。Gate 预先固定每块的正负和边界例及分配顺序，按声明的适用域与前置标签分配，不能按评分挑题。验证时使用相同环境种子、步数和原生配置做同游戏配对。现有门槛为有可靠性独有成功或至少两题模型调用节省，同时无可靠性回归、无策略错误；跨游戏有效技能还需实际介入并按冻结条件验证。只在被授权范围内使用，单步合法性检查、冲突回退、有限试用和配对退化暂停继续生效。同版本的 Gate 回执只能复用，揭晓的块不得用于新版本寻优。池不足保留 Shadow，不阻断其它合格学习或基础求解。试用有效期和终测是否有剩余资格必须在冻结前明确，不能自动重置额度。

## 7. 对照解释与统计

| 组别 | 操作及可支持的解释 | 解释边界 |
| --- | --- | --- |
| G | 成功轨迹编译、检索、复用、回退和原有治理全部启用的 FlowEvo | F−G 衡量加上失败策略学习后的整体增量，包括后续成功技能库可能随轨迹改变。 |
| F | 同 G，再从本组可信失败归纳可执行修复，并在通过 Gate 后调用 | 事后只挑实际介入题的胜率会有选择偏差；独立检查点开关比较才隔离单个技能的直接作用。 |
| R | 同 G，加普通额外求解。按上一完成窗口 F 新增的关联、生成、修订和验证模型请求数发放额度 | 排除一部分额外推理量的解释。匹配的是可用请求数，实际调用可能不足额，Token、费用、Worker、时延仍需分别报告。 |

三组各自维护成功库，采用相同初始状态、编译、治理、成功判定和回退规则。R 先锁定常规尝试，再按预注册顺序消耗额外额度并采用最后一次预定尝试作主结果；私有成败不用于选择。与其他组一样，每题只有主锁定成功轨迹可编译一次；额外尝试的中间轨迹不入库。R 发放口径只计 F 新增失败分支的调用。原生成功编译开销可能随成功率变化，仍记入各组总成本。三组同模型、温度、合法动作和 50 步基础上限；执行顺序轮换。最终评价不产生新学习额度，末个在线窗口尚未结转的 F 调用按冻结规则发放到首个评价窗口，另报 R 的实际预算差距。

删除 T 后，失去「同一套生成器只看历史任务描述，也能学到多少」的工作流参照。该组原先就同时改变入库样本、触发和信息内容，无法单独隔离失败轨迹的信息增益。对本研究的主要问题，成功学习本身已由 G 作为基线，R 控制普通额外尝试的部分资源影响。信息价值另由 B 的完整轨迹与简单摘要比较回答：相同失败选择、任务、模型、输出契约、生成机会和盲化验证，只改变可见证据表示。若需断言相对仅看题目的优势，再另做小样本同任务、同来源配对，主实验不恢复 T。前一版另设成功组 S 的计划由共同成功学习基线取代。

分别报告三个证据层级：

1. **生成可执行新技能。** A/B 报告可安全执行且去重的新机制、来源局部修正和有效技能/美元。源码能跑仅证明交付和执行。
2. **在新游戏修复问题。** 用独立 Gate 冻结的同游戏、同前缀和同成功库快照，在预先固定的适用检查点做失败技能开/关配对，另一支继续原生 FlowEvo。统计实际介入、恢复局部状态、整局恢复、无关/近似状态拒绝和反向退化。先锁候选及对照再解封结果；禁止用最终成绩筛选可用检查点。这个效应针对预定义的适用状态。
3. **提升强基线整体表现。** 最终 30 局比较 F−G 的配对成功率差、双方独有胜负、成本和不确定区间，定位为描述性；F−R 和在线 90 局趋势为次要指标。以游戏为配对单位并披露场景聚类；场景数足够时用预注册的场景组重抽样。单个任务流无法分离所有学习历史波动。报告样本覆盖、缺失敏感性和所有未介入结果；零介入的分数差无法估计技能效果。若将来进行确证性研究，按校准分歧率和最小重要差异确定独立游戏和重复流数。

## 8. 结束状态及运行前冻结项

| 状态 | 记录和解释 |
| --- | --- |
| 零技能产出 | 按定位、提案、交付、局部、来源、Gate 分解漏斗；报告真实输入和总成本 |
| 有授权、零介入 | 分开记录无匹配机会、拒绝、冲突、试用过期或在评估前耗尽；无已介入策略的收益估计 |
| 预算耗尽 | 辅助余额不足时记积压并继续有预留的基础配对；总预算不足按协议停止并报告覆盖率 |
| Gate 耗尽 | 候选保持 Shadow，报告待验证量、池分层与不可分配原因，不回收已揭晓块 |
| 运行中断 | 记最后完整边界、当前未决请求/Worker/环境状态和已计费用；仅从可审计检查点恢复。UNKNOWN 保留且不自动重发；环境无法恢复时报告部分结果和缺失 |
| 完整运行无性能提升 | 如实报告配对差异和成本，即使生成或复用本身成功 |

正式运行前还需冻结：

- 本地数据版本与完整清单、真实目录、排除原因、完整曝光审计、场景分组可行性、采样种子及 90/30 题序，外加各阶段互斥的 Gate 清单与分配规则。
- A/B 病例数、定位片段规则及窗口大小、局部比较范围和判据、整局与 Gate 阈值、消融同等输入条件、表示选择规则、试用到期及终测剩余授权处理。
- 模型/接口及报价来源、输出与上下文上限、各阶段费用授权、总账本预留公式、Worker 时间和停止条件、R 额外步数及未使用额度处理。
- 主效应与区间方法、最小有意义差异、缺失处理及只允许预注册的次要比较。签出代码及依赖哈希、验证器版本、恢复规则和审计公开字段。
