# 工作流策略算子：宿主代理修复契约 v1

实现位置：`FlowEvo/src/failure_evo/workflow_policy.py`。实验入口：`scripts/learn_reuse30.py`。本契约与旧 S1.1 的确定性修复算子分别版本化；没有修改旧制品或放宽其权限。

## 模型学习的内容

模型根据可信公开失败生成 `repair_operator(context)` Python 源码。适用判断、修复指令和拒绝理由由模型生成。宿主没有写入容量修复算法，也没有手工修改模型生成的策略。源码须通过静态权限检查，并在已验收的 Linux Worker 内运行。

当前工作流表示标识为 `python_host_repair_policy_v1`。允许返回：

- `{"status":"request_repair","instruction":"…","reason":"…"}`：申请一次宿主模型修复。
- `{"status":"declined","reason":"…"}`：拒绝。
- `{"status":"error","reason":"…"}`：明确错误。

不能自报 `applied`，不能变更模型、Token、注册表、权限、预算或评分。`instruction` 只是补充修复要求，宿主提供真实当前题目、候选和公开反馈；返回程序仍由宿主执行公开测试。

## 权限与费用

`max_model_calls=0` 仍表示 Worker 内不能调用模型。新字段 `max_host_model_requests=1` 表示宿主最多执行一次申请。Worker 不接触网络、API 密钥或宿主对象。两种字段不能混为一谈。

宿主调用与原生调用共用每题最多 5 次请求，不额外赠送额度。尝试策略前至少保留两次：一次策略修复、一次原生回退。某版本在同题最多执行一次，新生代每版本最多 5 次匹配尝试；拒绝、错误和公开验证失败也消耗已预留机会。所有模型请求使用 `PersistentBudget`，最终请求先预检，再持久化预留和发送。费用未知保留预留，报价估计不冒充账单。

## 准入与批次

静态通过只进入 Shadow。实际策略源码须在来源检查点申请修复，宿主真实模型返回的程序须通过来源公开检查，并通过通过状态、未知状态、预算不足和缺少题面等拒绝测试。宿主真实零额度拒绝检查证明无法绕过计费进入模型调用。以上证据经现有 `admit_nursery` 绑定源码哈希、来源事件和执行文件后，才允许有限 Experimental 试用。

这属于单来源基本功能验证，不代表跨题正确性或相对 Generic 收益。新版从下一批生效；旧版及失败记录保持不可变。已知违规立即暂停；两次真实尝试仍无验证成功或五次额度耗尽可冷藏；没有机会不自动判无效。本轮不晋升老年代。

## 30题试运行的研究边界

G/M/F 共用公开反馈底座、Python 提取器、成功经验库规则和解题预算。G 使用通用修复，M 在失败时加入模型归纳的文本经验，F 尝试已准入的策略。初始文本规格共用以控制知识来源，之后各组按自己在线历史演进。

S15 使用历史失败 warm-start，初始可调用算子为空。30道后续题分三批；全轮学习请求上限14次（包括M更新），最多两个机制族。最终复核等全部学习与路由结束后执行，不能用于选择来源、修订或晋级。曾参与历史评分开发的数据不能改称未见测试。

实际结果以 `runs/s15_learn_reuse30_20261022_01/30题真正学习—复用试运行报告.md` 为准。源码生成、来源功能、未来实际调用和研究收益必须分别报告；如果没有准入或调用，就不能把F的分数或成本差异归因于算子。
