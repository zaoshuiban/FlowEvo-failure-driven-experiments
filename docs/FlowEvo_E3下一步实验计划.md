# FlowEvo E3-W1：失败学习工作流小型试验

更新：2026-10-22。当前主线为 **Failure-driven Operator Induction + Generational Operator Memory + Cost-aware Workflow Routing**。本轮已完成零 API 材料准备与推进协议修订，没有启动新的付费生成、算子执行或权限授权。

## 1. 研究边界与三个问题

1. **RQ1，经验生成**：一次可信公开失败，能否形成在明确条件下可执行的恢复/求解策略？允许小程序、条件策略和宿主代理的模型修复决策，不要求复杂 AST 修复。
2. **RQ2，代际管理**：来源有效的候选能否受限进入新生代，在后续真实执行中被保留、收窄、修订、冷藏或暂停？保守拒绝本身不是准入成功；已知有害版本不得试用。
3. **RQ3，全成本收益**：与强 Generic 和同源文本经验相比，正确性与累计成本是否值得继续投入？生成失败、验证、路由、模型调用与回退都必须计入。

正式结束 `abc301_f` 数组容量、AST依赖和共享初始化循环拆分的专项研发。容量来源修复成功作为工程正例，过宽修改作为负迁移反例，v2持续拒绝作为过度保守反例。旧版继续 Suspended，未准入版本继续 Shadow；关闭研究线不等于抹去失败或把版本恢复使用。

保留预算、隔离Worker、失败事实、编译/一次修订、注册表、新生代额度及回退框架。此次不扩展静态控制流分析、不手工实现容量修复算法、不重建沙箱。

## 3. 首轮范围与材料

首轮最多两类工作流决策，每类一个初始候选、最多一次诊断驱动修订，不凑足数量，不要求先有三道同根因题。

## 5. Operator表示与权限：允许研究模型调用，保留宿主控制

现有 `direct_python_v2` 继续使用 `max_model_calls=0`，不改安全白名单，不让Worker获得密钥、网络、进程执行或预算句柄。

拟新增 `host_mediated_workflow_policy_v1`：模型生成的策略在受限环境读取公开上下文并返回**声明式下一步动作**，宿主校验后决定是否派发一个受计费的模型请求。允许研究的动作包括 `decline`、选择已有候选、提出候选代码和 `request_repair`。这属于新的算子表示与执行契约，不能把收益混记成既有零模型调用Python修复器的收益。

`request_repair`只能包含经协议验证的修复指令和受限参数。模型、目标API、工具权限、最大Token、次数、超时、公开测试、计价和权限由宿主决定；策略不能指定URL、密钥、文件、可执行命令或提高配额。策略文本作为受限用户内容，不覆盖宿主系统指令。

首轮每次策略最多提出一次宿主模型请求。宿主先生成最终请求、预检，再通过原PersistentBudget持久化预留并发送同一内容；生成源码仍交给原Worker，宿主重新公开验证。拒绝、格式错误、超时、测试失败则回到同一检查点的强Generic流程，费用保留。

**F策略调用与Generic回退合用每分支最多2次求解调用**，不能各自获得一套预算。宿主还必须为回退保留Token、时间及货币上界；余额不够时不试用Operator。未知费用保留预留，不能因为HTTP异常或策略declined就退款。

这条表示仍需实现与验收。当前准备脚本没有开放该动作，也未声称已经完成模型调用型Operator。

## 6. G/M/F公平对照与动态库

- **G-model**：当前问题、错误程序、可信公开反馈、共享工具和强通用修复Prompt；真实模型调用计费。候选保留等廉价规则对各组可用，不故意削弱G。
- **M-text**：在G上加入与F来自相同源事件的冻结文本知识卡；记录知识卡构建、检索/注入和续跑Token。
- **F-operator**：执行模型生成的策略或代码，重新公开验证，失败按同一剩余预算回退G；记录所有副作用与开销。

共享归纳若只物理请求一次，实验现金支出只算一次；部署情景账本要分别给M/F归属构建成本，不把F编译费用推给G。M不能获知F在后续任务上的未来结果，F也不能从最终评分更新路由。

首轮路由从已验收版本中按明确范围、权限、预算和冻结优先级选择；不新增学习型评分模型。无配对成本数据时记 `expected_saving=unknown`，仅以新生代试用额度探索，不能声称已节省。已知有害、暂停或冷藏版本不可路由；无机会不等于无效。

新生代准入沿用来源实际有效＋基本安全、边界、不适用与回退验收，最多5次范围匹配机会；不要求Generic不会修，也不要求先有跨题收益。**必须是Operator介入本身通过宿主验证；之后Generic兜底成功不算来源修复成功。** 本题形成新版本只可在未来题/检查点生效。

来源、开发和封存角色隔离；同一版本封存失败后不以第二名重试。更改策略、范围、Prompt或源码均形成新版本。新生代不自动晋mature，沿用已有真实复用、独立门控与配对成本规则；本轮不要求产生成熟算子。

## 8. 指标与继续/结束决策

完整记录：可信源事实→编译排队→实际生成/修订→来源验收→Shadow/新生代→题间发布→路由匹配→策略调用→宿主调用→验证→回退→版本复核。每条记录绑定版本、来源、任务、检查点、实际时间和费用。

区分匹配机会、实际尝试、主动拒绝、公开验证成功、最终复核成功；区分源题修复、工程变体、不同历史程序上的条件复用和自然新任务复用。最终复核只在锁定程序后进行，结果不返回生成器或在线路由。

```text
F累计净节省 = Σ(配对G本次完整成本 − F本次完整成本)
              − F归纳/生成/修订/验收/维护成本
```

F本次完整成本包括检测、路由、Worker、宿主模型、公开验证及回退。另报F对M的配对差异。Token、货币和时间分别统计；本地工具和人工成本未知记未知，不能视为0。试验做多个对照的物理支出与单一部署的归属成本分账；预期复用次数不是已回本次数。

最终可以得出：生成失败、来源无效、适用机会不足、条件复用有效但未回本、负迁移暂停、与G/M相当且更贵、或有值得继续验证的可靠性/成本信号。任何一种都可作为本轮完成结果，不要求成功算子数大于0。
