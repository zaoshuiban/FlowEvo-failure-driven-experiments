# 实验产物与公开仓库边界

本策略保护今后的提交，不意味着此前全部Git历史均已审计。

## 三类交付分开

1. 代码提交：实现、测试、公开接口说明。测试中的人工Mock样例需明确标识，不能冒充真实学习结果。
2. 协议冻结：公开经审查的摘要、源码SHA和归档完整性引用。非公开题目身份、精确Gate材料和评分答案保存在受控归档；不要自动把整个protocol目录发布。
3. 产物归档：原始请求/响应、生成源码、自测提案、Worker输入输出、评分、独立审查、权限和预算账本均留在仓库外。公开仓库只放经审查的报告摘要及SHA-256凭据。

真实答案、Gate密钥、凭据及非公开评审不得进入公开Git。含private/gold等词的路径只表示审计信号，不能单凭名称判定泄漏；反过来，文件叫summary也不能证明内容可公开。

## 提交保护

`.gitignore`忽略新产生的Run、数据、日志及私有目录。它不保护已经跟踪的文件，因此本仓库另有暂存区检查器：

```sh
git config --local core.hooksPath .githooks
python3 scripts/check_public_commit.py --staged
```

本机已配置该hook。新克隆也必须执行安装命令；Git不会自动激活克隆内的hook。不要使用`--no-verify`规避拒绝。检查器读取Git索引，不受“暂存敏感内容后仅修改工作树”的方式绕过；删除跟踪记录允许通过。

检查器拒绝私有目录、原始Run/数据、凭据文件、请求账本、非公开评分字段及已知凭据模式；reports只接受浅层Markdown和指定公开完整性/验证清单。需公开新格式时，应先做内容审查，再通过版本化策略和测试修改规则，不要改名伪装摘要。

机器规则不是完整的语义DLP：报告正文、图片、源码里的硬编码数据和未知凭据格式仍需要人工审查。不要因为检查器PASS就宣布没有泄漏。可在CI逐个检查新提交SHA，避免只检查干净工作树：

```sh
python3 scripts/check_public_commit.py --commit HEAD
```

当前没有自动配置远端CI或分支保护；本地hook可被明确禁用。正式团队使用应再设置受保护分支上的必需检查，并检查整个新增提交范围。

## 归档

运行以下命令之前先停止相关写入并创建公开报告目录：

```sh
mkdir -p reports/NEW_RUN
python3 scripts/archive_experiment_artifacts.py \
  --root runs/NEW_RUN \
  --storage "$HOME/.local/share/flowevo/controlled-artifacts" \
  --public-receipt reports/NEW_RUN/artifact_integrity_manifest.json
```

归档器拒绝符号链接、仓库内存储目标、归档期间的数据或目录漂移，并核对压缩包内每个成员SHA。完整成员清单保存在私有归档，公开凭据只包含整体归档和清单SHA、数量与大小，不暴露私有题目路径或答案。

本机存储目录0700、文件0400，macOS上设置并验证用户不可变标记。归档对象按SHA寻址，源文件不删除。属主可以显式清除不可变标记，因此这不是远程WORM、加密备份或灾难恢复服务；外部受控备份仍需单独部署与授权，不能谎称已完成。

不要把归档目录放入任何公开同步或公开下载位置。私有数据恢复应在受限目录进行，先核对公开SHA和私有成员清单，再由可信验证器读取；禁止将恢复材料拼接进模型提示。

## 已公开材料的处理

`.gitignore`或新提交删除文件不会删除旧Commit。若确认真实凭据泄漏，应先撤销/轮换；若私有测试已公开，应冻结受影响Run的独立性结论、标记测试曝光并替换未来确认集。随后确定Git历史清理、远端缓存及Fork处理方案。历史改写和强制推送需单独明确批准，不能自动进行。

本次f20d3220审计识别到的是工程Mock材料，未发现需轮换的真实凭据或需废弃的真实Gate题池；该结论仅覆盖该提交，不覆盖更早历史。旧Mock仍可能通过历史Commit访问，不能说“已经从GitHub彻底删除”。
