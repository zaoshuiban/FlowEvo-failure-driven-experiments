# FlowEvo：失败证据驱动的可信算子生成、晋级与阶段级路由

## 文档性质与依据

这是对用户《稳定失败驱动的可信算子生成与路由详细设计》的建议修订与下一阶段执行协议，不代表新增模块已实现或已有正面结果。保留原文“生成、可信、路由”三个研究环节、算子五元组与数据隔离原则，修改不适合稀疏失败和在线积累的部分。

依据：用户原设计第2、4、6—12节；E3-S0报告；可信任务集与R/G/F报告及逐题根因证据。本次只读核对的FlowEvo官方提交为36e81efd4d1fdbabca7366200b15808ebef157fa。服务器实际入口及修改版必须以运行清单和源码哈希为准。本协议中的新增规模、阈值、接口、文件名均是建议，不是官方默认配置，也不是服务器已有实现的证明。

## 一、研究目标与核心修订

目标仍为：从Agent自身运行的真实失败中生成可复用、可执行的Operator，经独立验证后，在后续任务中降低错误、修复次数或完整成本。

不要求错误必须是算法选择、DP状态或递推关系错误。数组容量、递归资源、空代码、输出不完整和无效修复均可形成候选。也不要求来源任务最终失败；已被普通Reflection修复的错误，可以研究其预防和成本节约。

将“稳定失败”拆为三个判断：失败事实是否可靠；是否值得启动候选生成；候选是否有足够证据获得执行权限。一条可信失败可以启动Shadow候选，但不能独自证明迁移或授权无边界部署。

暂定方法名：Evidence-Triggered Operator Induction（ETOI）。名称仅描述本候选方案，不声明文献首创。

| 原文位置 | 建议修订 |
|---|---|
| 2.2 基线 | 使用实际冻结的FlowEvo；回退到同一任务的原生下一步，不另起通用两阶段求解器 |

## 二、系统机制：双循环

任务循环：加载题初算子快照→FlowEvo原生生成/执行/修复→观察事件→已授权算子在固定Hook介入→返回并锁定最终候选→独立评分。题末才允许把该题公开可见的失败及修复经验加入发现池。

学习循环：积累可用证据→预算调度→结构化规格→有限候选生成→设计集筛选→冻结一个候选→独立门控与回归→发布或保持Shadow。新版本最早影响下一任务/下一批。

编译器和求解器可以使用同一个模型顺序运行，无需多Agent系统。编译、验证和排队成本显式计入，不假设免费后台计算。

保存两个独立命名空间：FailureEvidenceStore存事件及可信度；FailureOperatorRegistry存制品、证据和执行权限。原成功Skill机制保持共同基线配置，不为制造失败关闭它。

## 三、证据与生成调度

事件字段至少包括：event_id、stream_id、task_id、family_id、stage、candidate_sha256、parent_sha256、observation_type、finish_reason、input_legality_status、verifier_status、root_cause_status、observed_at、validated_at、available_from、visibility、source_evidence_ids、repair_evidence_ids、验证成本。

失败事实、原因解释、干预收益分别记录。

| 证据 | 允许的动作 |
|---|---|
| 未核验旧WA/超时/异常 | 分诊与排序，不冒充算法根因 |
| 空产物、语法不完整、长度终止且代码缺失 | 启动产物交付或工作流恢复候选，不要求数学oracle |
| 合法输入上的实际异常或可信错答 | 启动局部修复候选；原因未定时限定症状范围 |
| 最小反事实修复与正反测试 | 支持规格和边界，不等于跨任务收益 |
| 未见程序上的有益干预、误触发和回归结果 | 支持晋级与路由 |

finish_reason=length但已有完整代码时，不自动丢弃或续写。旧评分器错误、非法输入和基础设施异常不能直接编译成模型算法修复规则。

两条生成触发路径：
- 单见证：一条可信失败＋可检验干预目标＋有界验证方法，即可创建Shadow候选。
- 聚合：多个独立任务上的直接失败或明显恢复开销，用于提高编译优先级；相同症状不自动算同一根因。

建议题末触发首个高可信候选，其后每20题检查一次编译队列。固定最大候选数、总学习预算和冷却规则；没有新证据不重复编译同一族。

首轮最多2个算子族，每族3个初始候选、每候选最多1次设计修订、每族1次规格归纳，总计最多14次生成/修订/归纳模型请求。验证分支调用另计并单独设置上限；未获授权不调用模型。

## 四、算子规格与执行协议

保留o=(S,P,V,E,L)，只扩展原字段。

```yaml
operator_kind: workflow_recovery | code_repair | task_solver | prompt_policy
source_mode: historical_development | chronological_simulation | live_online
hook: before_native_retry
input_contract:
  task_public: ...
  candidate_code: ...
  public_feedback: ...
  generation_metadata: ...
  candidate_ledger: ...
  remaining_budget: ...
preconditions: []
allowed_actions: []
max_model_calls: ...
max_tool_calls: ...
decline_conditions: []
postchecks: []
fallback: resume_native_continuation
```

首版只接入before_native_retry和before_final_return两个Hook。每Hook最多一个算子，不做递归路由或互相调用。

返回结构：status=applied/declined/error；可选candidate_code或selected_candidate_id；validation_status=not_checked/structural_pass/public_tests_pass/failed；实际成本及证据ID。

applied不表示答案正确。算子不得修改沙箱权限、评分器、总预算或自行提升Active状态。资源改变必须由宿主按预定能力上限批准。新程序经结构与允许的公开验证后才进入候选登记；失败则按剩余预算恢复原生流程。

所有候选保留；“最近完整候选”“最近公开测试通过候选”与“隐藏最优候选”严格分开。前两者可作为预注册策略依据，最后一种只能用于离线上界分析。回退不返还已经消耗的Token。

### 首批目标

1. 主目标：产物不完整后的恢复选择。语法解析、length元数据读取是所有组共享的基础工具；待学习的是何时采取何种恢复动作和何时拒绝，不把基础检测器本身当创新。
2. 第二目标：可达索引域与分配容量不一致。已有阶乘表缺陷作为明确事后开发见证，不能在历史早期倒填。生成器需要产出有支持范围的分析/补丁/验证逻辑，不得无条件把所有n改成26。
3. 递归深度为备选，不要求同时做三个目标。不可无限提高递归上限、关闭隔离；是否用迭代恢复必须遵守任务语义和预算。

不强迫产生两个算子，也不要求通过门控的算子数量大于零。

## 五、可信晋级与路由

生命周期：draft→shadow→experimental→active；失败可rejected；证据失效或严重回归则suspended，随后retired或重新验证。

Shadow不得通过文本注入间接影响Agent。experimental仅允许预注册受控试验；active仅在绑定的源码、模型、范围、基线和预算内调用。

晋级分两条收益路径：可靠性提升；或在预设可靠性约束下减少恢复成本。不要要求效率算子必须至少赢两道原本失败题。

首轮小样本最多授予experimental。可将“至少两个独立检查点显示成本节约、目标集无观测可靠性下降”作为Pilot继续依据，但它不是总体非劣性证明。任何隐藏信息访问、越权、篡改评分或未授权费用突破均拒绝。回归和零误伤的不确定性单列。

三候选选优仅在D_des发生；冻结一个后才使用D_gate和D_reg。门控失败不能拿第二候选反复试同一门控集。后续版本使用新的封存门控分片；用尽则维持Shadow，不能挪用最终测试。

路由改为r(任务,阶段,候选,反馈,剩余预算,库版本)。先查证据和硬边界，再按冻结优先级排序。拒绝后续跑原FlowEvo，不额外启动两调用求解器。执行完成与有限测试通过、最终隐藏正确分开报告。

## 六、FlowEvo最小接入：不再更换整套运行栈

先核对已跑800题的真实入口和配置。官方src/code_math/runner.py的成功例库与src/eval/runner.py的编译、执行、治理系统不是同一条路径。本轮应冻结实际基线，在其上添加失败学习插件；不能同时更换运行栈、增强检索、修改模型推理配置，再将收益归于新算子。

建议模块名称（未声明已经存在）：

| 新模块 | 责任 | 原设计可复用逻辑 |
|---|---|---|
| failure_events.py | 事件、时序、可见性、证据引用 | E3-S0事件格式 |
| failure_compile_queue.py | 证据触发、去重、冷却、预算 | 修改stable_failure_gate |
| failure_operator_compiler.py | 规格、真实制品生成和有限修订 | failure_mechanism_induction、operator_runtime/generation |
| failure_admission.py | 开发筛选、门控、回归和撤销 | operator_tournament |
| failure_registry.py | 失败制品独立命名空间和状态 | operator_library，兼容现有轨迹字段 |
| failure_router.py | Hook、单算子、拒绝、原生续跑 | contextual_operator_router |

实际目录以服务器工程决定，避免重复实现已有公共组件。原设计称主后端为fixed_skeleton_prompt_only_v1；代码生成模块另存不等于已接入主闭环，必须记录每个真实生成制品的API来源与哈希。

插件关闭时，用固定历史响应验证模型输入、节点数、程序选择和返回策略与冻结基线一致。不以真实API随机输出的逐字差异判定兼容性。

可信评分、错误码、元数据、安全执行和费用记账作为共同基础，各组共享。不能让基线保留已知错误比较器而新方法使用修复版。

公开验证可以反馈给在线修复；最终私有评分在源码锁定后运行。一个隐藏PASS/FAIL比特也不能用于重试、Skill准入或后续算子更新。原路径若依赖这类反馈，应建立共同的公开反馈适配基线，并明确这是协议修订，不冒充未修改官方系统。

原成功Skill机制在各臂按相同规则、独立状态工作。不能把所有成功例复用关掉来获得更多失败；也不能分享干预臂产生的成功轨迹给其他臂。需记录基线究竟是完整FlowEvo还是简化FlowEvo-adapted code runner。

## 七、三种模拟与证据边界

### 原运行还原

直接复用E3-S0的800题、2132事件、8条流与依赖边。不再为了统计数量重新全审计。原失败库为0，只说明未部署新学习器，不说明新学习器一定有价值。

### 新系统影子模拟

新验证器在模拟时点只读取当前及过去公开字段。若新增诊断，必须在该时点执行或由仅依赖当前信息的确定性规则复算并计费。不得直接使用后续修复、E1标签或隐藏结果。

保留原8条流的独立性。研究共享库时另冻结任务级合并顺序，称为新模拟流；以题末/批末作为发布屏障，不用并行mtime制造跨流因果顺序。

两个事后验证的实现缺陷可以作为当前开发/Warm Start证据，不得倒填历史早期。冷启动使用时，需在相应时点重新形成可获得的验证证据并记录available_from。

影子模拟只报告观察、编译、门控、触发和潜在覆盖，不报告新系统端到端成功率。

### 真正干预后的续跑

一旦算子改变程序、Prompt、行动或可见反馈，后续候选必须由新分支实际生成/执行。仅在没有干预且请求完全一致时才可复用缓存。不能接回原历史l3/l4后把其成绩算作新策略成绩。

## 八、下一步实验阶段

### E3-S1.1：最小实现与透明性验收

新增模型API预算0。使用已有事件文件与可信评分接口，不再开展全数据集语义认证。

验收插件关闭不改变基线；Shadow不影响Prompt；题间发布；隐藏字段拒绝；拒绝回到同一检查点；算子超限终止；版本/证据绑定；未知用量非零预留；原始产物与新候选分别保存；空测试不算PASS。

人工故障探针仅用于工程验收，不进入自然失败计数或F经验池。

交付实际入口、最小diff、数据和动作接口、权限预算测试、信息时序测试。工程验收不要求出现研究性失败。

### E3-S1.2：候选生成与时序影子验证

主目标产物不完整恢复；第二目标容量见证，递归备选。最多2族，各3候选、最多1次修订，共最多14次生成类调用。门控调用、工具次数和费用上界另行冻结；未授权只设计和回放，不宣称候选已生成。

每族分开D_dis、D_des、D_gate、D_reg。真实历史故障作正例；完整程序、同症状不同原因、超范围代码作拒绝/回归例。参数变体不算独立程序。候选源码由生成器产出，不能先人工写好专用逻辑再包装成失败学习。

选一个设计胜出候选冻结后门控。报告证据可用、开始生成、结束验证、首次允许使用的四个时间点及成本。无可靠门控只保持Shadow。

已有800题、35题可信集、两个见证和已看过的R/G/F结果全作开发背景，不换seed伪装全新确认。

### E3-S2：固定检查点条件性干预

从来源/设计材料之外按预定顺序选最多24个真实历史检查点：建议12个目标失败、6个无目标错误的完整候选、6个相似症状或超范围候选。与来源任务、近重复/模板家族隔离。不人工注入错误填满正例；不足按实际数量。

这是开发性挑战集，不估计自然失败率。每个检查点在四臂中共享任务、代码、公开反馈、剩余预算和成功库快照。

| 条件 | 内容 | 作用 |
|---|---|---|
| B | 共同工程修复后的冻结FlowEvo原生续跑 | 原基线 |
| G | B＋仅由公开规格构建的廉价通用检查/恢复 | 排除普通工程恢复解释 |
| M | B＋与F相同历史证据的文本知识卡 | 排除只是提示/文本经验收益 |
| F | B＋真实生成、门控的可执行Operator | 被研究机制 |

在此条件性实验中，M/F共享证据内容、适用范围和触发点；M将知识作为文本给原生修复，F执行制品。制品的编译/验证成本必须单列。F若增加模型调用，其他组有相同总预算机会，但无需为了凑成本强制做无用调用。

G的Prompt和工具在API前冻结。对产物失败，至少包含合理语法检查、一次代码优先恢复及基于公开信息的候选保留；不能故意弱化。G可以得到从公共规格直接推导的容量或递归通用规则。

每检查点每臂一次：最多96个分支，不是96道独立任务。统一原生续跑预算，不用旧费用余额自动授权。记录恢复完整代码、最终有限测试正确、误触发、回归、拒绝、调用和Token。

F与G同分但成本更少可以继续；F/G/M无可复核差异则不扩展该算子。零触发需区分没有适用机会和路由失效，不能直接宣称无用。

### E3-S3：60题真实顺序流

阶段E3-S2出现可信条件性收益且获批预算后才运行。60道未参与设计的新题，建议TACO/LCB各30；按元数据和可信准入冻结，不能按模型失败筛选。没有足够题则事先缩减。

3个连续批次，每批20题。B/G/M/F使用相同任务顺序、模型和预算、各自独立状态。主轨失败库空库冷启动；当前批次可用公开证据经独立门控后，下一批才可用。最后一批编译但没有使用机会的制品仍计成本，不虚构收益。

Warm Start可作为独立诊断轨，明确预载的是历史事后证据，不与冷启动合并。最终隐藏评分不回传，门控使用预先封存独立分片；用尽不再晋级。

F影响后续代码时必须真实运行。60题单顺序仅作可行性证据；后续是否增加顺序/独立流重复另行预注册，不根据有利结果挑顺序。

后续可另设30道冻结库测试，单独测纯复用效果；不是本轮强制执行内容。

## 九、指标与成本

分别报告：
- 事件：直接可信事件数、独立题数、证据等级；旧WA仅信号。
- 形成：生成候选数、真实制品数、Shadow/experimental/active数、首个生成和首次复用位置。
- 复用：未来触发率、实际执行、拒绝、误触发、跨题目家族覆盖。
- 可靠性：首稿/最终完整性、有限测试正确、目标恢复和非目标回归。
- 成本：在线Token、工具资源、编译、门控、审查和治理；未定价人工成本不能写零。

统一口径下：

NetSaving(N) = Σ[C_B_online(i) - C_F_online(i)]
               - C_induction(N) - C_gate(N) - C_learning_audit(N).

F_online包括检测、路由、算子、原生剩余续跑和回退。不同模型价格、工具秒数和Token不能直接混加。实验为对照多跑的分支费用与部署所需成本分账。

准确性与节省并列，空输出较便宜不是效率优势。没有实际配对基线或预先随机干预，不更新净胜统计。挑战集的条件恢复收益、自然流的触发频率和完整摊销成本分开。

不把版本数当独立题数；在线题目共享动态状态，不套用简单独立同分布推断。正式统计优先基于独立题流/顺序重复和合理分组。

## 十、停止与继续

取消以下不必要前提：必须是高级算法错误；必须最终失败；必须先出现3道同错才生成；必须增加最终正确率才能保留效率算子。

保留以下边界：评测争议不是算法证据；单见证不是泛化；Shadow不是在线效果；提示模板不是确定性代码算子；故障注入不是自然失败；简单Generic同成本已覆盖时不能仅为方法名称扩展系统。

工程通过：插件有来源、隔离、撤销、时序与费用证据。
条件性收益：F在新检查点相对G/M有准确性或恢复成本增量。
自然流收益：实际积累、编译并复用，完整净收益可接受。
仅种子收益：明确报告Warm Start或局部回归，不外推自然积累。
未触发：报告适用机会与证据不足，不补造失败。
