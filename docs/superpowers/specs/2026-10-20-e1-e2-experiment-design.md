# E1 / E2 冻结实验协议

状态：待用户审阅，尚未抽样、调用生成 API 或报告实验结论。

## 范围与方案选择

采用先完成 E1、再从审查合格的历史检查点开展有预算上限的 E2。全量人工审查 800 题成本过高；直接从所有 WA 启动修复会混入评测问题。因此选择分层审查加小规模配对实验。现有重评结果只作为抽样框，不作为根因真值。

基线为 repair_v2/epochs/repaired_reports_20261020 的 800 题及 2132 个历史候选。保留代码、任务、反馈、评分器、环境、输入集合的 SHA256；不修改历史产物。新证据与新调用独立存储。

## E1：无生成模型的审查

1. 旧最终失败且新规则 WA 的 171 题抽取 50 题。
2. 最终运行异常类全部审查：2 道超时、2 道编译错误、1 道运行错误，共 5 题。明确披露不足 10–15 题；不把无完整代码或早期候选混作最终异常题。
3. 旧失败、新 PASS 的 64 题抽取 20 题。
4. 旧 PASS、新 WA 的 18 题全部审查。

以上是 93 道不同任务。先根据题意建立任务家族标签，再按来源、难度、家族比例分配配额，使用最大余数法和 SHA256(seed=20261020, task_id) 排序抽取。小层合并规则、配额、候选全集及抽样名单在深入检查程序之前冻结；人工修改标签留下原因。没有 LCB WA 是实际样本框特征，不补造此层。

每题保存题意约束、原始程序及哈希、原始与新反馈、触发测试、输入合法性核验、独立期望结果依据、沙箱实际输出/异常和复现命令。用穷举、暴力 oracle、数学不变量、合法构造验证或人工可核算轨迹作独立证据。候选修复只用于最小反事实验证，不替代原程序，也不进入成功率。

隐藏测试可以在隔离审查资料中复核，但不得进入 E2 提示。E1 不调用生成模型 API。不能独立证明输入合法、期望结果正确或缺陷所在的题，保留未知。

三个互斥主标签：VERIFIED_ALGORITHM_FAILURE、VERIFIED_EVALUATION_PROBLEM、ROOT_CAUSE_UNKNOWN。另记录算法选择、状态/转移、边界/下标/初始化、修复退化、I/O、评测/参考数据等根因子标签及证据强度；多种机制可并存，比例分母必须写清。旧误判而新 PASS 的程序仍须证据验证，不能仅凭新 PASS 宣称程序正确。

输出冻结抽样清单、93 题证据卡、可复现命令、分类统计及未知原因。分层抽样的原始比例不外推为全部 800 题比例；如估计抽样框总体，提供分层权重并说明全查层。

## E2：相同检查点的配对修复试验

从 E1 已确证算法/实现错误的任务中，按预先冻结排序选择最多 12 个任务，每题选一个仍失败、且历史上真实发送过修复请求的检查点。检查点必须是当时实际修复输入，不能拿最终代码拼装旧反馈。每任务一个检查点，避免相关候选重复计数。

优先选择旧反馈类别确有错误的检查点；旧、新反馈语义相同者只作为负对照，单独报告。现有 2132 条记录中确有新 WA、旧反馈为 Runtime error 的 75 个候选，但必须经过 E1 证实才能入选。若合格任务不足 12，报告实际数量，不降低证据要求。原程序已经正确的误判样本只可作为独立的改坏风险观察，不计入算法恢复率，且本轮不额外增加调用。

R0 使用历史真实修复提示及旧反馈；R1 只替换错误反馈块为可信标准类别；R2 在 R1 基础上加入公开机制产生的合法反例。其余题意、代码、历史技能上下文、系统提示、模型参数与预算一致。恢复历史修复提示无法做到的检查点不得冒充严格因果样本。

R2 使用与隐藏测试隔离的生成器：仅依题意约束和独立 oracle，固定种子公开生成测试，并对原检查点检测、缩减反例。冻结生成器及搜索预算，公布搜索成本；不得复制、改写或根据隐藏失败输入定向构造反例。若固定预算内没有公开反例，该任务不能进入三臂主分析；披露排除及其选择偏差，保留两臂诊断结果。

每臂 2 次独立重复，每次仅允许 1 次修复调用。最多 12×3×2=72 次调用。每次 max_tokens=32768，总新增 API Token 上限 3,000,000（含输入、输出和可报告的推理 Token，不重复计数）。调用前按输入 Token 估计加最大输出预留预算；超过余额不发起调用。无额外生成器模型调用。API 失败及重试也计入调用与成本台账，不能突破上限。

沿用历史请求的模型标识与参数，记录服务返回的实际 model、usage、请求 ID、时间、延迟、错误和响应哈希。历史请求模型与实际返回模型曾不一致；先检查配置和本轮返回值。本轮各臂必须来自同一实际模型；若服务无法保证，不将结果解释为严格模型控制下的因果证据，暂停剩余调用并报告已用成本。

所有修复输出用同一冻结隐藏评分器评分。PASS、FAIL、不可评分分别报告；不把不支持检查器记为算法失败。主指标为每次单调用恢复率和任务级平均配对差 R1−R0、R2−R1，报告样本数及以任务为聚类单位的不确定性；小样本只作探索性证据。成本报告每臂输入/输出/推理 Token、调用数、恢复每题成本和延迟。没有可核实价格时不编造货币成本。

## 验收与失败处理

必须交付实际执行记录，而不是仅交脚本或方案。E1 未完成、合法公开反例不足、历史上下文缺失、API 不可用或预算耗尽均明确披露，不编造完整性和显著性。新增工具用已知真值样例验证分类、反馈隔离、预算封顶、哈希一致性和统计分母；E2 提示发布前自动检查未包含隐藏测试字段、参考解或 E1 私有证据。

本协议不能保证获得 12 个合格因果样本；若不足，有限样本本身是结果，不以未验证任务补齐。
