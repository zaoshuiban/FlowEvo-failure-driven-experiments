# Route C：下一轮实验决策

日期：2026-11-18。最终建议：**`ENGINEERING_FIX_FIRST`**。

这不等于认定七局都由工程Bug导致。原因是已确认的静默动作替换会混淆“模型提出什么、环境执行什么、反馈说明什么”，影响后续失败机制的学习与归因；应先单独处理这一问题，再决定真实技能训练。本轮仅审查，没有修改原生算法。

## 2. 为什么先处理工程接口

838次原动作请求中，36次执行第一条合法动作回退、19次从全文匹配；其中38次有明确Act/执行偏差，分布在3个失败和3个成功游戏。其余17次是Act与Think同一行等格式情况，不能全部记为错误。供应商响应均完整结束。

例如第2局要求放置毛巾却连续执行检查台面；第10局要求回原位置却实际关柜。环境没有返回Nothing happens，是因为收到的已经是另一条合法动作。这类问题应该通过统一动作交付与诊断处理，不值得训练新的专项恢复程序来补偿。

建议下一项独立工程任务限定为：

- 保留原始模型意图、严格解析结果、是否在合法列表中，以及真正执行的动作。
- 对不能接受的输出返回明确结构/合法性诊断；不得由宿主猜正确修复动作，也不得静默执行首个合法动作。
- 若允许模型重选，必须冻结次数并计入G/R/F相同的动作请求预算；已收到的请求不自动重发。
- 不在该工程修复中同时实现搜索策略、Cup/Mug别名或任务专项算法。
- 用旧838份响应只读回放，区分可兼容格式偏差和真实不合法选择；运行零API回归。新协议与旧113/120成绩分开。

是否加入持久状态摘要也必须明示为共同基础能力或单独工程对照，不能悄悄只给F。最近10步/120字符的截断是原协议事实，并非已证明的缓存损坏；改变它属于协议版本变化，需要独立评价。

## 3. 后续最小机制实验草案（未授权、未启动）

先做分阶段来源/迁移实验，暂不启动大规模在线性能实验。

### 阶段C0：工程忠实性与收集规则冻结

完成上述解析修复的离线验收，冻结原生成功学习、holdout、动作预算、完整历史接口与成本口径。可将简单公开状态账本作为G/R/F共同工程基础，另存旧基线作版本参考；或设置独立工程基线E，但不能把E混入F独有方法。

准备新的自然失败收集流，按任务类型/场景元数据随机抽样，不按未知成绩挑题；全部结果保留。与封存60局、Route A/B学习及已曝光游戏分开。原7局仅为已曝光开发材料。

建议进入技能训练的最低探索条件：目标机制至少来自**3个不同游戏、2个场景**，其中至少2局为自然完整失败，并存在可以只用前缀识别的锚点；另有相同信号但能成功的正常/恢复案例。这个门槛是资源投入条件，不是统计充分性保证。达不到即报告 `MORE_NATURAL_FAILURE_DATA_NEEDED`，不无限追加或用人工制造失败替代自然失败结论。

### 阶段C1：小规模技能获取

优先一个机制，最多2个初稿、每个最多1次来源反馈修订。只允许来源公开前缀、合法执行反馈和已锁定历史失败；不给人工探针位置、获胜路线、本报告根因标签或独立评价结果。可以弃权，不补采样凑成功数。

共享当前环境技能接口与Worker。每份源码/版本/成本独立保存；来源修复通过后仍是Shadow，独立验证和权限条件不满足不得进入正式答案。生成与修订费用必须计入F完整成本。

### 阶段C2：同检查点G/R/F对照

可规划12个不同游戏的独立局部状态：6个真实恢复机会、3个正常成功过程中的相似信号、3个证据不足或不适用状态，至少3个场景。这是待验证的数据可行性目标，不是已准备好的清单；标签与锚点须在候选运行前冻结，不能按F表现选择。

| 组 | 行为 |
| --- | --- |
| G | 修复后冻结的原生full_library，保留成功经验和原生治理 |
| R | 同一G，在相同公开触发点按冻结规则获得一次额外普通诊断/重规划机会，不读失败学习库、不调用新增技能 |
| F | 同一G、同样公开触发与总环境步数，允许经过资格检查的冻结失败恢复技能介入；拒绝后原样回退 |

三组从同一可校验状态启动，使用相同基础模型、原始成功技能库快照、合法动作、终止规则和**原任务剩余50步额度**。不得对F重置50步，也不得让R看到隐藏结果后挑答案。R额外调用产生的计划何时注入、是否占用动作调用，必须在协议中写死。

主要终点：不同游戏上的环境确认局部修复、原生失败是否被挽救、原生成功是否被破坏。次要终点：合法但无关的动作、拒绝/UNKNOWN、余下步骤、原生调用、Worker时间和全部成本。只完成局部动作不能报告整局收益。

R与F至少预先匹配**费用预算上限**，同时报告实际输入/输出Token、模型费和Worker资源。F的离线学习成本不能算免费；除观察到的复用次数摊销外，还应报告未摊销总成本。等调用数不等于等费用，预算上限匹配也不等于实际计算严格相等。如果R没有消耗全部额度，保留这个差异，不追加请求凑结果。

如果来源成功轨迹足够，可增加成功经验策略对照；在样本不足时先不强行增加组数。当前历史成功12/107可帮助构建子目标保护的开发负例，23可展示有效取回；它们不能再充当独立测试。

## 4. 本轮证据支持与不支持的结论

支持：原生完整失败中存在公开可观察、可程序化研究的循环和状态维护问题；一些局部前提改变有真实历史环境效果；有明确的动作交付工程缺陷。

不支持：7局共同一个根因；所有重复都错误；只要记忆完整就一定获胜；L1未将Mug匹配Cup是Bug；旧人工捷径可以作为原生可执行知识；新失败技能已产生增量；正式在线安全已经通过。

成功对照的作用是检验边界。严格停滞代理见5/7失败和7/113成功，不能将后者自动视为误报；其中有真实低效而自行恢复的过程。主张必须由后续同状态干预与新游戏验证支持。
