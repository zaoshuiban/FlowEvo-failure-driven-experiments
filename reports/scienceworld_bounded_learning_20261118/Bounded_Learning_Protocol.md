# ScienceWorld：一次有界的电路失败恢复学习

2026-11-18。用户已要求开始 ScienceWorld 实验。实验只覆盖 `power-component`，不扩充任务族、不改造 FlowEvo 主执行器。机器规则、源码与 JAR 散列记录在 `runs/scienceworld_bounded_learning_20261118_01/protocol.json`。

## 研究问题与边界

在原生代理真实出现电路操作反复无效之后，模型能否从失败轨迹及实际执行反馈生成恢复程序，并改善未见变体的结果？只研究这一种失败。训练阶段如果确有同类卡住后自行成功的轨迹，可加入真实恢复后缀；否则不预先声称材料包含恢复过程。不检验“纯失败信息优于成功信息”。

ScienceWorld 1.2.3，官方 `power-component` 的 train 为 0–9、dev 为 10–14、test 为 15–19。只按顺序扫描 train；dev 保留不用；所有 test 只在程序冻结后运行。环境无简化，每局最多 60 次代理动作尝试。官方 reset 隐含的 look around 单记，实测模拟器 moves=0。错误动作、自由观察动作及消歧编号均占一次代理额度。

基线是本轮冻结的通用文本行动代理，不称为 ScienceWorld 官方论文基线或已有 FlowEvo 原生适配。所有组收到相同的任务描述、当前反馈及免费 look/inventory、完整动作/原始响应历史、初始观察、25 个普通动作模板和剩余步数。历史不重复保存每一步的免费 look/inventory 文本；当前免费观察始终提供。模型自由提交一行命令，宿主直接执行，不从合法列表替换。reset 命令禁止。模型输入不含任务/变体 ID、评分、内部 goal progress、全局对象树、合法动作预言、金标准计划。

## 先确认一个真实失败，再学习

公开触发信号：已经尝试过 connect；最近六次动作里，同一个电路动作（connect/disconnect/activate/deactivate）及其原始响应至少重复三次；任务尚未终止。检查点还须剩余至少 12 次动作。单独重复 look 不算电路失败。

每个训练变体先把原生执行跑完。遇到首个“有上述检查点、原生最终仍失败”的案例立即停止筛选并开始学习；最多扫描十个训练变体。该失败及最多两个此前出现同类信号的真实轨迹成为开发材料。没有合格自然失败则停止，交付筛选记录和零次学习，不人为造错或换任务凑结果。

学习模型沿用 `deepseek-flash`、DeepSeek 官方 `https://api.deepseek.com/chat/completions`、temperature=0、thinking disabled。最多初稿一次及修订两次，每次最多 8192 输出 Token。模型独立生成 `environment_operator(context)`、适用条件和解释。人工提供接口、执行与评分，不写恢复策略。

无害的额外 JSON 字段保留并忽略，不丢弃源码。修订收到上次原始源码、精确交付/静态错误及真实开发执行反馈。程序只在原有无网络、只读、限时 Linux Worker 中执行。开发续跑不允许用原生回退来补足候选成功；另以开发例初始状态检查程序是否拒绝过早介入。

首个通过全部开发续跑且拒绝初始状态的候选立即冻结。否则三次请求后，按开发成功数、初始拒绝、较少错误、较少动作、较早版本选择最佳可执行候选；须明确它是否通过验收。没有可执行程序则报告未学出程序。测试成绩绝不回流修订。

## 冻结后的配对

固定测试全部五个官方 test 变体。先跑完整原生轨迹；取首次满足触发且至少剩 12 步的状态。原生后来成功的触发态也保留，用来观察误介入损害。没有触发则取首次成功 connect、仍未终止的状态作为正常进展对照。没有检查点也记录，不换例。

| 组 | 执行方式 |
| --- | --- |
| G | 同一冻结基线继续执行。 |
| R | 额外一次最多 1024 Token 的普通重规划，再由 G 执行；不提供学习材料或程序。 |
| F | 冻结程序逐步行动；拒绝或候选错误后，G 从已经修改的当前状态及剩余额度继续，无回滚、无再次介入。 |

三组共享逐步重放核验过的前缀、公开起始状态与 `60−prefix` 额度。精确相同模型请求共享响应缓存，缓存命中仍计逻辑调用。R 的额外规划与 F 的程序执行不是严格等计算量，只用于辅助判断额外思考收益。

成功须为环境终止且官方分数 100；部分分数、超限和失败终止均不是成功。分别报告自然触发态、正常进展态的成功数，`G失败/F成功` 的救回数、`G成功/F失败` 的损害数。仅在共同成功的配对上计算调用与动作节省。模型真实请求、缓存、学习成本、重规划、Worker 与动作尝试分开计数。每个 variation 是一个独立测试单位。

## 成本与必要工程

全实验硬上限：1600 次真实请求、800 万账本 Token、10 美元保守费用预留、1200 次 Worker 调用、四小时。学习另受三次请求限制。10 美元是保守账本上限，不是供应商实际账单。原请求在发送前保存；可能已发送但无结果的请求不自动重发。

三个 JVM、九次导航/观察前缀重放已一致；这不保证所有电路状态确定性，所以每个正式检查点继续逐步核验观察、分数与 moves。基础设施错误立即停止并保留记录，不伪装成候选失败。现有 Worker 烟测、交付解析、缓存/计数和动作边界已检查。工程到此收束，后续只执行冻结试验。

## 执行中的基础设施补记

首轮学习请求已返回、尚未执行候选或接触测试集时，训练变体1的开发重放发现同名颜料杯的显示顺序改变。官方1.2.3渲染按对象name排序，对同名对象没有稳定次序。独立诊断16次完整17步前缀，其中10次逐字匹配；其余只出现杯子描述排列差异。

原机器协议、原源码、账本和学习材料均原样保留。另冻结 `Runtime_Amendment.json` 与 `run_scienceworld_replay_resume.py`：所有后续开发及测试臂最多重放16次，且仍受原四小时截止时间约束。只有初态和完整前缀每个反馈字段逐字相等才接受；已诊断的杯子显示排列差异仅允许重试，不允许作为相等接受。其他文本、评分、moves或终止标志差异立即停止。所有拒绝与接受、动作数和时间另行记录，绝不按候选结果选择重放，也不把重放失败反馈给学习模型。

此修复没有追加首轮请求、增加学习次数或费用上限。它保证的是相同公开前缀与剩余预算，不是完整隐藏状态快照；原始隐藏状态未捕获，1.2.3的其他潜在非确定性仍是结论限制。G与原生原后缀逐步一致的核验继续保留。
