# 候选版本缓存修复

日期：2026-11-05。结论：确认存在代码级缓存身份不完整，已修复；没有发现由此导致未经授权执行的实际证据。本轮零付费模型，未改历史记录或既有授权门槛。

## 修复范围

复用operator_contract.binding，新增统一candidate_identity：新契约使用完整绑定，并核对声明的candidate_version；旧协议保持其原代码身份。新契约绝不回退到代码哈希读取旧记录。

- SealedGateProvider：评审文件、请求模板、输入Schema、REVIEW_FROZEN与返回包均绑定完整候选版本。新契约评审协议为sealed-math-gate-provider-v2，必须包含candidate_version；仅复制旧评审到新文件名仍被拒绝。
- PoolReviewedRelease：完成、待审、延期、开始、恢复及作业目录全部使用完整身份。sha字段继续作为代码溯源，不再作为新契约缓存键。
- 修复延期记录缺artifact引起的恢复错误；新记录完整保存工件，旧legacy延期仅可从相同legacy身份的待审记录恢复；同次poll按版本去重。
- CumulativeStream等待评审判断改读统一pending_records，A已完成不能遮蔽B的待审状态。
- ReviewedRelease核对评审包的candidate_version；Gate冻结查询也核对版本。
- VersionGate对冻结重复、Gate消费、试用续期和已用次数按完整版本隔离，避免新契约被旧版本的记录错误跳过或阻塞。
- 人工评审模板工具同步生成v2字段。工程Mock提供者同步字段，不修改其数学算法。

旧代码协议的v1评审与旧队列继续兼容；未版本化的旧新契约缓存不会被自动升级为新版本成功。历史日志不改写。实际Run使用前仍需重新冻结源码和协议。

## 验收

15个新增针对性场景，含继承回归共33项通过；相关9模块组合227项通过（含继承重复，不跨批相加）。覆盖：

1. 同源码、同旧语义契约，只改新Operator Contract，A/B完整身份和评审路径不同。
2. 代码哈希命名的旧评审不被新契约读取。
3. 复制A评审到B路径仍拒绝；A/B分别冻结。
4. A的完成记录不能满足B；未版本化代码级完成记录不能提升为新契约成功。
5. B的新Gate目录及完成恢复独立、同版本不重复验证。
6. A中断不误命中B；延期记录可恢复并只poll一次。
7. 相同Gate数据的冻结与消费按候选版本隔离。
8. A完成不能关闭B评审等待；legacy延期只恢复对应legacy队列。
9. 旧v1评审兼容；声明版本不符拒绝；错误版本包在执行前拒绝。

实际Linux Worker发布路径：使用独立的工程Sum夹具、模拟模型与宿主夹具Oracle，让A先实际完成安全、SOURCE、Gate、未来Shadow和发布；随后只改Operator Contract构建B。验证B返回待新评审，未继承A完成结果、评审前无新Worker调用，队列中A完成与B待审并存。
