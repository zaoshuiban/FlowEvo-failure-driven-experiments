# 24 题 Protocol A 自动 Gate 启动检查

当前真实 Pilot 为 **NO-GO**。自动验证路径通过工程验收，实际 24 题与其独立自动验证材料仍需绑定。评审人、公钥和独立账户仅在选择签名模式时适用。

| 检查项 | 当前证据 |
| --- | --- |
| 自动验证器 | 复用 Linux Worker、SplitRunner 与宿主精确有理数判定。先验证静态安全，再用冻结参考独立核对 SOURCE 和 Gate 的参数、适用性与数学答案 |
| 权限 | 自动数学验证通过后仍经过 Shadow、现有配对发布 Gate 和有限授权。缺少覆盖或安全收据时为 UNVERIFIED，数学结果不符时为 BLOCKED |
| 隔离和重复试探 | 预检核验原题、谱系、曝光声明与池哈希。验证按完整候选版本审计。同组一次测试池启动额度，既有收据供同版本恢复 |
| 实际数据 | 待提供 24 道有可核验官方原题身份的在线题及私有评分，独立 Gate 池的来源、曝光登记，以及可复现的适用性和参数映射 |
| 运行冻结 | 待绑定干净源码 Commit、Worker、任务顺序、模型报价、本轮硬预算、分析规则，再做真实配置的零 API 预检 |

零 API 工程夹具使用真实 Linux Worker 和模拟模型。正确夹具在无人工评审文件的情况下完成 SOURCE、独立自动 Gate、Shadow 和发布。同源码的新契约版本触发已消耗测试池的阻断。缺少静态安全收据时无 Worker 执行。错误答案对照触发数学阻断，同版本重试返回已有结果，未启动发布模型账本。零 API 组合单测也覆盖缺少验证器或冻结映射的预检拒绝、池漂移、签名兼容和旧版本权限隔离。真实 Pilot 付费请求为零。

自动模式的可信范围限于冻结映射覆盖的候选和精确有理数结果。新的候选契约可能没有适用映射，即使整轮启动准备通过也可能全程只有 Shadow。正式泛化协议允许使用可信自动验证，继续要求独立任务、来源证明和可审计证据。

用户需提供或指定 24 题及独立 Gate 的真实材料和项目曝光记录，提供可用的独立映射或可复现参考程序，并确认本轮预算。现有 50 题学习诊断版保留其独立冻结状态。 [配置及证据要求](../../docs/research_evaluation/AUTOMATED_GATE.md)
