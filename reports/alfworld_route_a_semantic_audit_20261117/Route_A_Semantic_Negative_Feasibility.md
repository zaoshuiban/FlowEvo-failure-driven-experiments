## 3. 阶段冲突：要区分动作作用域

| 动作作用域 | 可评价内容 | 不允许的推断 |
|---|---|---|
| OPEN_PREPARATION | 打开是否真实发生，是否改变容器状态 | 尚未加工→任何打开都是错误 |
| FINAL_DELIVERY | 具体被投递物体是否具有任务要求的当前加工状态；能否满足最终目标 | `move`合法→任务完成；未获胜→所有中间放置有害 |
| PROCESSING_ACTION | 当前具体物体的加工是否成功，是否被后续反向操作失效 | 加工过另一个物体→当前物体已加工 |
| INFORMATION_GATHERING | 观察、库存是否补充了必要公开证据 | 任何观察变化都是任务进展 |

本轮只新增宿主审查词汇，不向运行时加入动作规则。`move`在语法上是放置，只有结合策略声明、目标及证据才能将其评价为最终投递；动作字符串本身不能证明意图。

### 3.1 已有真实回执

18个UNPROCESSED分支的闭门投递都真实失败；随后参考`open`成功，重试`move`均合法并有效，但**18/18未获胜**。这些记录包含真实执行及独立reset重放。

旧审查器在`route_a_expanded_labels.py:62`拒绝把整个状态标为DECLINE，是因为“未加工时打开可能只是准备”。它没有执行“仅禁止无加工前提的最终投递”的新作用域评分。因此连续得不到阶段负例，一部分是**所要求的宽泛状态标签与可证实的动作级问题不一致**，不是完全没有可检验的加工前提。

### 3.3 分类结论

| 情形 | 分类 | 证据与限定 |
|---|---|---|
| 未加工时打开目标容器 | NOT_A_NEGATIVE | 环境允许准备动作；18条真实成功打开 |
| 确认未加工却当作已完成的加工物体最终投递 | VALID_NEGATIVE_POSSIBLE | 目标要求同物体加工状态；18条合法放置但未获胜；只能评价最终投递作用域 |
| 公开历史不完整，没看到加工回执 | UNRESOLVED | 缺失不等于物理上未加工；继续UNKNOWN，不自动改成可信DECLINE |
| 允许先放下再取回加工 | NOT_A_NEGATIVE | 3/3宿主继续重放可以获胜；不说明中间操作有净收益 |
| 尚未加工便启动任何恢复都必须拒绝 | UNRESOLVED | 当前环境不能据此证明所有可能的准备动作错误 |

公开证据可以包括同一实例的成功加工回执和明确物体状态描述；历史必须保留范围、完整性及顺序。私有环境状态或评分可帮助宿主核验，但不能伪装成候选当时可见的事实。若无法给出可靠的公开前提，标签必须保留不确定。

## 4. 实例冲突：此前构造换的是容器，不是加工物体

采集器`prepare_alfworld_route_a_a1d.py:67`先找到并持有一个subject；`OTHER_INSTANCE`仅对目标容器候选执行`choices=choices[1:]`。物体subject没有换，且非UNPROCESSED分支会先加工它。于是，它实际测试的是：

> 已加工的同一物体，能否投递到另一个同类容器？

当前目标使用存在量词约束容器类别，没有要求“参考路线中的柜子1”。12个OTHER_INSTANCE分支全部合法投递并获胜，完全符合环境语义。

| 情形 | 分类 | 结论 |
|---|---|---|
| 仅因换了同类目标容器编号而判错 | NOT_A_NEGATIVE | 当前类别目标允许；12/12真实回执获胜 |
| 要求当前四类标准任务指定唯一`apple 1`／`cabinet 1` | NOT_REPRESENTABLE | 本轮48个实际目标及对应模板没有该约束；不能改目标文本伪造 |
| 加工A后换成未加工B，却沿用A的加工证据 | VALID_NEGATIVE_POSSIBLE | 加工条件与投递共享同一变量；这是处理证据身份错配，不是偏好某个编号。本轮尚未构造交换分支 |
| 公开指代“它” | UNRESOLVED（若对象不能确定） | 同一任务对象需同时满足目标条件，但不能仅凭代词声称目标固定为研究者选的编号 |
| 双物体任务重复使用同一物体 | VALID_NEGATIVE_POSSIBLE，当前技能范围外 | 原生`pick_two_obj_and_place`有`not (= ?o1 ?o2)`，同时要求两物体在同一容器；不能用它冒充当前单物体技能的已验证能力 |

所以，原来“至少3个同类目标容器编号冲突”的要求在当前采集语义下不是尚未幸运找到，而是**没有目标约束可支持该标签**。但“实例绑定风险不存在”同样不成立：加工证据必须绑定当前被投递物体，合法动作也绑定当前真实位置与实例。

## 5. 本轮额外发现的待验证边界

实际域中加热与冷却会互相清除状态。冻结门控的`_processed_ok`（源码第174行）找到一次匹配的历史加工动作／反馈便返回True，没有显式处理之后反向加工使状态失效的分支。

这构成**静态审查发现的潜在过时状态风险**，不是本轮实际候选误触发结果；本轮没有运行门控或恢复程序，也没有改写既有零误触发成绩。若以后验证，应在新协议中事先冻结“当前同实例加工前提”及动作作用域，不要用“曾经见过heat”代替当前isHot。

此外，任务目标类别、当前所在位置、实际交互对象和目标容器不能合并为一个身份概念；处理证据可迁移到同类对象的假设也不能成立。当前安全检查不应因唯一编号目标不存在而放松。

## 6. 是否值得继续采集

**不建议继续使用原UNPROCESSED／OTHER_INSTANCE命名和标签期待，盲目增加同类游戏。**

可以提出新的、待冻结的限定作用域方案：

1. 阶段审查只评价“未经当前同实例加工证据支持的最终投递”，对准备性open、观察和真正加工分开计量。
2. 实例审查区分“允许互换的同类目标容器”与“加工证据／持有物体错配”，不要求环境没有定义的唯一编号目标。
3. 缺失公开前提保持UNKNOWN；若环境与公开证据均不足，不以私有真相强行要求模型作确定判断。
4. 可加入加工后状态反转的作用域审查，但须明确其为新检验目标，不能追认为原3个实例／阶段负例已经补齐。

这属于任务书的**情形B：部分原设负例不符合真实任务语义**；同时存在可以在明确作用域内验证的加工与同实例前提。不是情形A的“已补齐覆盖”，也不能因静态风险直接宣布情形C的“候选已实测出错”。是否属于情形D的“自然失败机会稀少”，必须等P2历史原生轨迹审计，当前没有数字可报告。

原48局NO-GO不变；若采用限定作用域方案，必须形成新的前瞻性协议及决策，不能事后删除原阈值。本轮未冻结P1新游戏，没有消耗其48任务组／20,000步建议额度。后续优先进行无需付费的历史机会审计，再判断定向采集和在线实验的价值；本轮到P0为止。
