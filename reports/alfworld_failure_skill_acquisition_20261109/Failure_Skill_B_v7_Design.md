# B v7 固定机制的失败有效性和目标绑定

使用 v4 已冻结的跨容器机制与它引用的 11 条公开来源分析，仅生成一份新策略。策略学习目标是判断失败是否仍然有效、同当前目标是否一致、此时是否需要接管。沿用模型生成的 environment_operator 接口，不提供原 v6 源码或七个错例的答案。v7 实验不重新归纳，也不研究失败前预防。

生成要求分三项。Failure Validity 观察失败后的状态变化，历史位置只是线索。Target Binding 核对任务物品、持有物、目的地实例、失败动作和最终投递阶段。Recovery Decision 在前两项有证据时才选相关合法动作，障碍已由外部解除或无法确定时拒绝，避免接管原生动作。一次正常观察不会自动使相关失败失效。自身恢复过程的后续动作也需检查目标及未完成状态。

来源和负例沿用 v6 冻结清单。4 个实际失败后的来源检查点为 33、40、88、72 局，重放到确切的失败反馈。原生历史后缀和候选从相同检查点对照。短恢复可通过，允许继续至最多 12 步且受剩余 50 步预算约束。首个动作是否正确开目标、同一投递恢复合法、同物同目标实际投递和环境获胜分别记录。20 个负例按 11／6／3 分组，无新增正式样本。

可观察诊断把介入或拒绝视为触发结果，目标容器实例及投递物品视为绑定结果，合法性变化与执行回执视为恢复结果。理由字段可辅助源码审查，但不能作为内部判断正确的证明。通过条件仍是 4/4 局部修复、0/20 误触发及 0 接口错误。任何版本保持 Shadow，独立泛化另设实验。
