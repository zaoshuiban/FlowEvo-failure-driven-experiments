# ALFWorld B v10 学习可验证的技能适用条件

B v10 将学习与检查分开。P 根据 B v4 的冻结机制及其 11 条公开来源轨迹，提出一套可检查的条件或明确弃权。V 在 36 条冻结开发记录上逐条检查同一份提案。模型选择角色、条件及组合，宿主通过公开证据给出三值结果。待执行的修复描述留作诊断记录。适用性判断通过也不代表已经验证局部修复或整局获胜。

| 历史依据 | 本轮测量 |
|---|---|
| v4 提出了跨容器共同机制，原归并交付因字段超长被拒 | 复用既有 provenance 和 v5 的只读归并重验，P 只学习适用条件 |
| v5 失败后来源修复 4/4，但出现误触发 | 同时报告正例覆盖和错误介入 |
| v6 工程修订后来源修复 4/4，负例误触发 7/20 | 持有变化、状态改变和旧失败冲突必须可观察 |
| v7 来源修复 0/4，负例误触发 1/20 | 单报低误触发率会遗漏过度拒绝 |
| v8 目标类别与实例识别有正向信号，失败有效性判断仍不可靠 | 把公开证据是否足够与最终适用性判断分开 |
| v9 D/S 在共同完成的 30 条上分别答对 24/22 条，S 的 8 个正确 YES 均被一致性检查标记 | 不能用 v9 的矛盾标记整体替代条件评估。未知批次 S_03 保留 |

输出区分模型弃权、输出无法交付、条件不合法、条件合法但检查器不支持、缺少公开信息以及已确定的 TRUE/FALSE。V 完成后评分，按真实来源、已曝光历史回归、合成状态分别报告三值矩阵、冲突、正例覆盖、明确错误介入、过度拒绝、合理弃权和信息不足时的介入。保留条件数量、重复表达、引用与逐条运行时证据，记录模型 Token、费用估算与本地检查耗时。

开发筛查只做明显失败的粗筛。正例覆盖为零、出现明确误介入或在参考 UNKNOWN 上介入，均记为开发证据不足。满足粗筛仅表示可以继续审查，候选始终处于 Shadow 诊断用途。全拒绝的候选即使误触发为零也不能通过粗筛。

历史 D 在相同 36 条记录上的结果随 v10 输出保存为描述背景。它使用 v9 的直接判断提示和逐状态调用，P+V 使用 v4 公开来源学习并复用一份规则，信息、调用方式和 Token 使用均不同。本轮没有新的严格配对因果比较。后续严格对照应先冻结同一待评状态、同一来源信息访问、模型和预算口径，再分别报告一次性学习及逐状态的计算成本。开发条件表现合格后，还需要锁定候选和解析器，在未曝光游戏中验证，并单独验证候选动作的可执行性和修复效果。

本轮主要回答 P 是否能交付可检查条件及 V 能否区分应介入、应拒绝和信息不足。零 API 测试只证明流程和检查器工作，真实模型能否提出有效条件仍待 Pilot。
