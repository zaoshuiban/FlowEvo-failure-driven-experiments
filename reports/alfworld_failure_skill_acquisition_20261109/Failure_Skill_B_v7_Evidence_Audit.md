# B v7 输入、输出与安全审计

固定机制与引用的原始公开分析通过 v4 归并请求、响应与证据哈希重新绑定。实际生成 payload 只有 mechanism 与 analyses。v6 原始源码、宿主工程修订及 20 个负例只用于宿主历史核对和验证。新策略在运行时只能访问公开目标、观察、合法动作、已发生历史和自己的有界状态。没有读取独立 Gate，也没有提供人工探针、未来状态、合法性标签或手写修复程序。

原静态检查禁止模块顶层非字面量计算，使候选业务逻辑在受控函数调用时才执行，避免导入时先触发任意调用。生成契约明确允许模块常量为字符串等字面量，正则匹配或编译在函数中进行。顶层 re.compile、计算常量、装饰器、注解、默认参数及模块自测不允许。沿用原安全检查、沙箱与运行时合法动作检查，无权限调整。

保存原始响应、原始生成源码、静态拒绝原因、Worker 账本。源码完整交付数、静态拒绝数、Shadow 注册数及实际 Worker 调用分列。真实 v7 无宿主工程修订分支。验收的 v6 工程修订源码只作为 Mock 响应夹具，历史成绩、原始交付与新 Run 成绩分开。固定 v6 负例的作用域、SHA 和三组标签均核对一致。
