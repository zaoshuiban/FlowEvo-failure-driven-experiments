# B v12 通用技能表示与生成可靠性

B v12 保留公开证据、三值逻辑、Linux Worker 与 Shadow Registry。三类候选使用同一表示和执行入口。人工夹具只用于检查表示和执行链路，独立存于 Mock Run。

## 表示与绑定

| 能力 | 验证内容 |
|---|---|
| 容器状态与连续动作 | 在失败锚点确认投递无效果，分别检查打开及重新投递是否可执行 |
| 台灯位置与交互 | 将待检查物体和交互工具分开绑定。显式公开观察可绑定承载表面，缺少观察时保留未知 |
| 导航及子目标进展 | 从公开合法命令探索。通过同一条二元命令将物体和拾取位置绑定，确认持有后再检查目的地及投递 |

新选择器只读取公开观察或合法命令。候选可以按既有规则使用同一类别，或要求明确的实例相等。二元命令参数来自同一命令及可核查的角色关系。匹配到多个实例时不随意取一个。没有加入容器、灯具或来源编号的恢复规则。

## 入口、继续和停止

交付时对条件表达式做有界的布尔可行性检查。若所有规则都无法同时满足入口为真、首步守卫为真、停止为假，则拒收。还单列永远无法在停止为假时触发的继续规则。超过 12 个不同原子时记为未穷举。这个检查可发现结构性矛盾，实际环境是否存在可行动状态仍要回放。

`event_is` 检查已匹配的回执，缺少证据时保持 UNKNOWN。新增 `event_recorded` 检查指定公开前缀是否已有某个绑定对象的指定效果记录。没有匹配记录时可以判 FALSE，仅说明当前可见前缀，不能推断隐藏状态。角色未绑定、失败锚点缺失、动作可能匹配但回执不可判时仍为 UNKNOWN。停止结果为 TRUE 或 UNKNOWN 时，执行器照旧拒绝。通过显式证据将“尚未记录完成”表达成 FALSE，首步才可以继续。

## 扩展版提案只读诊断

- 容器原提案仍因 OPERATION_ENUM 不合格。独立逻辑检查发现入口与停止冲突，两个动作规则在停止为假时都不可行。
- 导航原提案仍因 OPERATION_ENUM 不合格。它还把一元导航动作的唯一参数绑为 failed_target。v12 提示明确该参数是 failed_subject。
- 台灯原提案结构可接收，三个来源仍分别得到 ENTRY TRUE、STOP UNKNOWN，均被拒绝。继续使用规则还要求与停止式相同的原子为 TRUE，逻辑检查标记为不可达。原绑定实际指向书、笔和枕头。v12 不修改原候选或历史成绩。

真实 Pilot 使用扩展版已经通过归并的三项机制和原始公开证据，每个机制只生成一次。11 个容器、3 个台灯、9 个导航来源固定在生成之前。通过交付的候选依原流程回到 23 个已曝光来源检查点及 21 条同样的边界控制，按候选与分层记录结果。每分支仍为最多 18 步及原局剩余步数。原始模型响应和评估记录独立于 Mock 夹具。

## 零 API 验收

38 项测试通过，包含 7 项 v12 专项和 31 项 v8–v10 回归。另用三份独立手写 Mock 夹具走真实 TextWorld 和 Linux Worker，共 146 次 Worker 调用。

| Mock 夹具 | 来源获胜 | 21 条边界上的明确误触发 |
|---|---:|---:|
| 容器 | 11/11 | 2 |
| 台灯 | 3/3 | 2 |
| 导航 | 7/9 | 6 |

三类在同一接口内均产生了真实环境动作和获胜回执。导航未赢的第 85 局达到 18 步上限，第 113 局在 5 步后无合格动作。每份候选都运行相同的 18 条明确负例与 3 条信息不足控制，三个夹具均无信息不足时的介入，也均因明确误触发未通过开发筛查。Mock 成绩只证明表示及执行可用。

同一 Mock Run 重新进入后，三个模拟请求、预算账本和 Worker 记录均复用。已验证发送 UNKNOWN 阻断重发，禁用授权拒绝启动。732 个历史文件哈希保持一致。
