# ALFWorld B v14 恢复计划编译与修订

B v14 沿用 B v13 的三类冻结机制、23 个已曝光来源检查点和 21 条开发边界。六份 B v13 响应已按原契约只读复核。三份初稿同时存在轨迹引用和角色对象格式问题，三次修订只修正了引用。原响应、成绩和账本保持原样。

## 计划交付

模型用自然语言描述障碍和完成标准，用短动作短语提交有序恢复步骤。角色可以直接引用目标类别、失败动作参数、持有物或明确的公开绑定方式。前置条件和停止条件使用有限的短语，模型无需手写谓词对象、条件 ID 或 Worker 源码。证据只暴露 `s001` 这类短步骤引用，每个引用由宿主绑定到唯一原始步骤。生成输入保留原始公开动作、观察、失败时的合法命令和既有模型机制假设。

编译器从模型声明的步骤生成现有 Worker 接口。解释文字不产生动作。计划可以用 `failed_first` 和 `failed_second` 明确绑定已观察的失败动作参数，也可以选择从公开回执、观察或合法命令中解析角色。目标类别本身不能作为具体实例，找不到唯一依据时保持未知。

## 分阶段检查

| 阶段 | 检查与产物 |
|---|---|
| Schema | 一次返回所有可独立确定的引用、字段、类型、枚举和动作参数问题。每条有路径、代码、期望和实际值。依赖不可读字段的检查列为 `CHECK_BLOCKED`。 |
| 策略逻辑 | 结构通过后检查角色依赖、互相矛盾的状态、尚无法存在的成功回执，以及各阶段能否在停止条件为假时执行。 |
| 公开来源状态 | 在冻结的失败后公开前缀上检查是否能选出首个合法动作。记录类别或实例绑定、前置和停止状态，不执行环境动作。 |
| 环境执行 | 修订结束后，候选经过现有静态安全检查，以 Shadow 身份进入真实 Linux Worker 和 TextWorld。分开记录首步有效、局部修复、计划完成和整局获胜。 |

策略逻辑检查能排除部分已知矛盾，实际状态是否满足条件仍由来源诊断和环境回执确认。

历史查询区分“最近一条匹配回执”和“在完整的公开窗口内是否曾记录匹配回执”。窗口及角色已知且没有匹配记录时，存在性检查可返回 `FALSE`。缺少绑定或回执无法判定时保留 `UNKNOWN`，停止判断为 `UNKNOWN` 仍拒绝。有限重复只能依据当前公开状态或合法动作，执行阶段由环境回执推进。

## 修订规则

每类机制一次初稿、至多两次修订。只有 Schema 拒绝、策略逻辑拒绝，或冻结来源均无法选择首步时才触发修订。部分来源可选择首步时，保留覆盖差异进入冻结验证。修订包包含上次计划、编译与公开状态诊断、可引用步骤 ID 和失败动作类型。公开状态诊断只提供条件值和绑定状态，不附带正确动作、替代路线、已选动作、Worker 回执或 Gate 结果。超出发送上界时记录阻断，避免只发送部分诊断。

每次尝试保留响应和请求哈希、阶段结果、改动字段及诊断差异。区分不再报告、持续报告、之前已可检查后新出现、此前被阻断而现在首次可查，以及现在无法核对的错误。移除某条错误不构成策略正确或语义等价的证据。

## 零 API 验收

12 项 B v14 测试和 46 项历史回归通过。三份手写计划夹具共消耗六次 Mock 响应和 62 次真实 Linux Worker 调用。容器夹具首轮同时收到引用与角色格式诊断，修订后才进入策略逻辑检查并暴露停止冲突，第二次修订通过。台灯夹具首次编译通过，公开来源状态诊断发现首步不可用，触发一次修订。导航夹具初稿直接通过。重进同一 Mock Run 时，模型请求、Worker 回执和费用账本未重复消费。模拟第二次修订的发送状态未知后停止，旧请求未重发。

| 工程夹具 | 首动作有效 | 局部修复 | 计划完成 | 整局获胜 | 明确负例误触发 |
|---|---:|---:|---:|---:|---:|
| 容器 | 11/11 | 11/11 | 11/11 | 11/11 | 2/18 |
| 台灯 | 3/3 | 3/3 | 3/3 | 3/3 | 1/18 |
| 导航 | 9/9 | 0/9 | 9/9 | 0/9 | 2/18 |

九次信息不足控制均拒绝。导航夹具的计划只覆盖一次替代移动。三份夹具均有明确误触发并保持 Shadow。手写夹具结果用于工程验收，真实模型对新交付形式和两轮修订的表现仍待测。
