# B v10 零 API 验收

31 项测试通过，包含 10 项 v10 条件与 Pilot 测试，以及 21 项 v8/v9 回归。持久化 Mock 使用 11 条冻结学习轨迹，收到一次模拟提案，再对 36 条开发记录执行检查。重复进入同一 Mock Run 只复用一次已结算回执，发送次数和费用账本均不重复。真实 Pilot 目录仅包含冻结协议、数据、预检和禁用授权模板。

| 验收 | 结果 |
|---|---|
| 公开条件 | TRUE、FALSE、UNKNOWN 分别覆盖。缺少观测不会推断关闭 |
| 身份、持有和阶段 | 类别相同与编号相同分开。明确冲突可判 FALSE。拾取、处理、打开回执带时序证据 |
| 作用域与可见命令 | 拒绝外来步骤引用。区分一个与多个同类别合法命令实例 |
| 交付与能力 | 模型可弃权。无效条件、合法但不支持的条件、公开证据不足分别记录 |
| 组合与过度拒绝 | 验证 all/any/not 和适用、拒绝冲突。零误触发且无正例覆盖的候选仍被判开发证据不足 |
| 标签隔离 | 换掉参考标签只影响评分。学习请求逐项与公开来源投影一致 |
| 恢复与安全 | 已结算回放、预算上限、授权拒绝、发送 UNKNOWN 阻断通过。历史 v9 账本哈希不变 |
| 发布边界 | 候选记录为 SHADOW_DIAGNOSTIC_ONLY |

Mock 夹具故意只用两个原子，检查物体类别与容器状态。它覆盖 8/8 应恢复案例，也错误允许 5/24 个明确负例及 2/4 个未知样本，开发筛查判为 `INSUFFICIENT_DEVELOPMENT_EVIDENCE`。在 24 个明确负例上，另外 7 条为 FALSE、12 条为 UNKNOWN。该结果证明测试能够同时看到正确介入、错误介入和信息不足。提案由测试手写，不能用于评价真实模型学习能力。
