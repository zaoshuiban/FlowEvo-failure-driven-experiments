# B v11 通用恢复技能 Schema

模型提出的机制、可执行结构及原响应分别归档。提案可返回 ABSTAIN 或 UNSUPPORTED_REPRESENTATION。PROPOSE 需要原机制的全部轨迹 ID、每条轨迹的失败锚点、角色、条件、入口表达式、可选停止表达式、动作规则、适用范围与拒绝说明。

| 层 | 结构与含义 |
|---|---|
| 证据 | 归属使用轨迹 ID，条件使用机制来源公开步骤 ID。源锚点、步骤作用域、时序由宿主核对 |
| 角色 | 固定选择器分别绑定目标物、目标客体、失败动作的主体/客体、当前持有物。动态选择器从同类别合法命令绑定唯一实例，或按公开记录选一个尚未成功到访的可达位置 |
| 关系 | category_equal 比较类别，instance_equal 需要两侧实例明确。bound、state_is、goal_requires、action_available、selected_failure 只查看公开状态 |
| 时间 | event_is 支持 before_failure、at_failure、after_failure 和 entire_prefix，区分 effect 与 noop。只看已观察到的动作及回执 |
| 条件 | 原子返回 TRUE、FALSE、UNKNOWN，组合用 all、any、not，保留每个原子的判定及证据 |
| 操作 | 最多 8 条有序规则。只采用守卫为 TRUE、参数有具体绑定且属于公开合法动作的规则 |
| 停止 | 入口只在首次执行时检查。之后每步重新读状态及规则。显式停止表达式为 TRUE 或 UNKNOWN、没有可用动作、无进展、同公开状态重复操作或达预算时结束 |

缺少当前证据时保持 UNKNOWN。目标按类别描述不会自动推出实例相等。已记录的拾取是历史事实，当前持有从可解析的最新公开状态和回执独立建立。锚点收到的 no-op 可以是可肯定的事实。缺少历史事件不能推断环境中该状态不存在。

模型可组合如拿取、放置、处理、打开、关闭、查看、交互和导航动词。宿主只实现各动词的公共语法、观察回执、可见命令实例及三值计算。比如导航选择器只枚举公开列表中尚无成功抵达记录的位置，无法知道灯具在哪，也不会将来源未来位置写入检查结果。模型必须自己选择何时使用选择器、如何排序动作规则及何时拒绝。

Structured 产物不是模型生成的 Python。宿主把冻结动作描述编成一个通用 Worker 适配器，按显式绑定拼接命令，再经既有静态检查、Shadow Registry、Linux Worker 和环境执行边界分别核对。Worker 使用公开目标、观察、动作前缀、合法命令和本次选定规则参数。没有机制分层、任务编号、参考标签或后缀评分。适配器代码和候选版本的哈希与原始模型响应分别保留。
