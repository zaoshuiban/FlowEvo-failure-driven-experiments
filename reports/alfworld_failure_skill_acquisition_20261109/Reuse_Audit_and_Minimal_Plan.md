3. 现有静态规则拒绝导入时执行、越权导入及错误入口。Worker 在限制内运行精确源码，测试合法选择、无效动作、异常、超时及拒绝。任何规范化和格式诊断均不改写代码。
4. 三类手写夹具用同一接口经过真实 Worker，检查一次一条动作、下一步接收新观察、JSON 状态按分支隔离、步数耗尽终止。夹具证明接口能力，正式结果只采用模型源码。来源执行单列有实际效果的首步、局部证据、修复完成和 `won`。合法但无进展、过时失败和错目标均应可辨别。
5. 修订包只含允许的先前版本和真实开发反馈。测试初稿、两轮修订的请求标识、父链、源码改变后的新版本绑定和已知结果去重。只改变描述不得为同源码增加开发试探或获得授权。
6. 模拟已结算响应后崩溃、候选检查点已提交后崩溃和发送状态未知，检查恢复按已提交事实继续，费用及模型请求不重复结算。未决 Worker 需核查，确定性环境前缀的恢复重放独立记账，并与原回执逐步比对。已完整执行的分支从绑定回执恢复，出现状态分歧即停止。
7. 所有候选保持 Shadow。真实结果、Mock、开发边界和独立评价产物隔离。原生成功学习及已有运行入口的历史回归保持通过。未冻结独立协议前不运行 Gate。

## 5. 未解决问题与结论边界

**已从源码和工件确认。** 本地普通 Python 路径曾让模型生成的策略通过真实 Worker 和环境执行，且对来源检查点的触发时机敏感。B v14 也确实运行过模型计划对应的导航首步，局部修复仍为零。未见研究候选跨容器、台灯、导航三个机制共同通过真实来源开发验收的记录。发布状态和成本计量可从上述原始回执复核。LearnAct 的默认 ALFWorld 执行器能跨多步访问环境，训练错误反馈与直接宏执行可在源码分别定位。论文规模、测试成绩及论文训练划分按论文描述报告。本次未复跑上游。[v14 实际结果](</Users/majiatong/.local/share/flowevo/alfworld_recovery_plan_v14_pilot_20261112_01/result.json>)、[LearnAct 实现](https://github.com/zhao-ht/LearnAct/blob/80c9348d23afcec4b3811da6e1d8b6ee43c27777/model/learnact_agent/learnact_learner.py#L878)、[COLM 论文](https://openreview.net/pdf?id=KqK5XcgEhR)

**还需实际验证。** 模型是否能利用逐步反馈修订成正确策略、是否能表达非容器机制、是否能维持拒绝边界与低开销、能否在未参与生成和修订的游戏上迁移，均待测试。若某机制的恢复依赖当时从公开接口无法取得的状态，按信息缺口记录。若公开证据足够而模型选错目标或停在一次移动，按策略不足记录。不能因一个来源无法匹配就改变冻结任务或补写答案。

- **工作流可行性。** 用相同冻结来源和边界比较旧计划路径与拟议 Python 路径，报告交付、执行、局部修复、误触发与完整成本。若同时改变表示、反馈来源或修订预算，只能比较两套流程。按每次尝试保存版本级结果，保留未触达及失败，不能由最终最优版本反推单个组件的效果。
- **失败证据的独立价值。** 待开发有可信候选，再冻结独立游戏与检查点。比较保留原生成功学习的 G 与 G 加失败驱动可执行能力，并可加入仅使用同源文本失败经验的组。共享基础模型、环境、任务顺序和原生能力，记录学习、复用及回退资源。报告同检查点局部修复、整局胜负、误触发、负迁移、不同游戏或场景的配对结果。若要归因到失败轨迹的信息增量，还需在相同可执行接口和相近生成预算下对照所见信息，例如真实完整轨迹与失败摘要。复用上游修订组织只提供实现路径，研究效果来自独立执行证据。

### 六项审计回答

1. **LearnAct 最值得参考的组件**是 `find_failed_step` / `wrap_history` 对失败调用和子步骤的整理、`optimize_tool_step` 将旧代码绑定执行证据的修订流程，以及训练内重放后选择候选的做法。
2. **可以保留逐步接口与安全 Worker。** 普通 Python 每次返回一个合法动作或拒绝，宿主持有环境、记录动作与回执并显式传回状态。
3. **上游带来额外调用、信息和手写知识。** 包括 Actor 选宏、候选采样、说明和用法生成及修订。环境对象提供更宽访问，示例还覆盖容器、实例绑定、台灯和导航。此次只复用流程思想。
4. **可以绕开自定义恢复计划语言。** 现有 Python 接口足以表达有状态的多步动作并让宿主验证。三个机制都由模型学好、都能可靠修复，仍需要后续实验。
5. **Pydantic 可替代交付格式校验。** 覆盖字段、类型、枚举、长度、额外字段和路径级错误，并从同一定义导出 Prompt Schema。证据合法、源码权限、角色绑定和实际恢复由独立检查判定。
6. **最少新增三个文件。** 一个交付与反馈适配模块、一个来源 Shadow 试验入口和一个零 API 测试文件。验证真实回执能进入有界修订，代码原样进入 Worker，开发结果和权限隔离，恢复及计量不重复。
