# B v8 自主绑定与宿主解析方案

当前A/B是两项诊断，不是两种学习算法的性能对照，也不是新的技能生成。

|能力|方案1 自主生成绑定逻辑|方案2 宿主通用解析|
|---|---|---|
|类别/实例提取|由模型生成代码|宿主提供解析器，属于人工工程能力|
|时效与恢复决策|模型生成|模型生成|
|输入信息|同一公开快照|同一公开快照及仅由其派生的字段|
|是否允许标准答案|否|否|
|完整实现状态|待诊断后决定|只预留接口，未实现解析器|

same_information_view 仅接受公共白名单，复制输入后交给解析回调，并返回公开快照哈希及 host_derived。该接口不证明任意外部回调可信，后续仍须审计解析器代码、输入范围及确定性，禁止闭包、外部检索或硬编码参考表作为Oracle。没有把本次参考标签接入运行时。

若比较两方案，冻结同一来源证据、相同模型资源和策略接口，分别统计解析、绑定、时效、执行与成本。宿主派生字段可能改善计算便利性，但不能将这种人工能力计为失败学习贡献。可以离线输入人工可信字段做故障定位，必须单独标注，不能充当正式在线收益。

当前六个研究问题的回答如下。

1. v7四次来源拒绝直接发生在类别目标与带编号实例的字符串匹配，另有OR条件放过错误目的地。后续环节尚不能判为正确。
2. 四个来源公开前缀可支持局部绑定，不能推广到所有游戏。
3. 多实例无消歧、当前持有物未知、必要加工阶段未知、当前障碍证据不足，应输出UNKNOWN。明确矛盾则CONFLICT，不用UNKNOWN掩盖。
4. 可以独立测量A与B，并报告B在A正确子集的表现，尚未获得真实模型数值。
5. 可以在不提供人工修复路线的情况下开展诊断Pilot，需新的明确费用授权。
6. 完整B v8策略生成仍未就绪。先取得真实诊断结果，再决定自主绑定或宿主解析对照，不因Mock全对提前发布技能。
