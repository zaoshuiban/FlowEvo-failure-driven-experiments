# ALFWorld 失败技能自主获取设计 · B v2

正式 G 组为 113/120。本轮先检验能否从 16 个真实的局部失败与恢复事件中获取可执行技能。7 局整局失败继续支持原 A 协议，暂缓真实运行。两个来源集合均已曝光。原生成功学习和治理保持现有实验语义。

## 三段式获取

1. **逐条分析。** 按冻结原序分成两批各 8 局。每条返回锚点反馈引句、可选的恢复反馈引句、原因假设、恢复假设和不确定性。锚点是原生 L1 最后无效动作。宿主逐字核对步号和反馈，每条保留一个分析或弃权，因果归因保持假设。任一批交付失败，保留已接收的分析并停止后续阶段。
2. **机制归并。** 一次调用接收通过核对的非弃权分析。模型根据兼容的原因与可执行操作归并，也可以保留单例、留空或弃权。每条证据在一次归并最多支持一项提案。仅有相同失败现象不足以合并，模型必须描述兼容依据和限制。归并结果可追溯到引用的原始动作和反馈，宿主不因结构合规就认可共同根因。
3. **逐机制生成。** 按支持游戏数降序、不同恢复引用数降序、最早原始位置、机制哈希排序。最多为前四项各生成一份 Python 策略。保留未选、拒绝和重复源码记录。每个机制最多按冻结原序取前三个已引用检查点，少于三个时全部保留。此过程不读候选验证成绩。生成接收该机制及其引用分析，输出原样交给现有安全检查、Worker 和 Shadow Registry。所有曾见 B 证据都绑定候选来源身份，机制支持数只用该机制的引用。

A 与 B 的证据数量、组成和终局信息不同。若后续要判断恢复后缀的信息增量，应在同一批 B 检查点上另做前缀与前缀加后缀的配对消融。

## 来源验证与记录

同一游戏重放原前缀、执行原动作并核对环境回执，然后从同一前缀分叉。候选只能看到当时公开状态和分叉后实际发生的历史。前 4 步形成短窗口；同一分支允许继续到最多 12 步，始终受原 50 步剩余额度约束。所有机制使用相同上界，候选可提前拒绝，宿主不替其选后续动作。扩展继续使用 Worker；原生模型续跑须另行授权与计量。

| 状态 | 证据要求 |
| --- | --- |
| LOCAL_REPAIR_VERIFIED | 原动作无效，候选恢复了原本不可用的关键动作。将替代分支公开状态与原真实恢复中紧接决定性动作之前的状态精确比对，且该决定性动作在原回放中提高得分或使环境获胜。 |
| EPISODE_WON | 候选实际执行后由 TextWorld 判定获胜。局部证明与整局结果各有字段。 |
| PROGRESS_UNVERIFIED | 动作或公开状态发生变化，缺少可信推进证据。 |
| REPAIR_FAILED | 候选执行动作只产生无效反馈。 |
| DECLINED / POLICY_ERROR | 分别记录不介入和接口、权限或执行问题。 |

来源状态匹配只证明公开检查点上的修复证据，不证明隐藏状态等价。当前没有为所有可能的搜索、子目标或占用错误建立通用语义 Oracle；缺少可观测证据时保留不可验证。记录原动作与同动作视野内的历史后缀，以便比较动作开销。归并、源码与执行的候选漏斗分别计数。统计每阶段请求、实际 usage、估算费用、账本预留和 Worker 耗时，单列来源检查点通过、整局成功、拒绝和异常。来源验证不产出发布权限。
