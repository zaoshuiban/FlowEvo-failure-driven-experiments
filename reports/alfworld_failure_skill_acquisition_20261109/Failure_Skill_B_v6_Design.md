# ALFWorld B v6 固定机制下的失败后恢复设计

## 既有实现审查

v3 的保险柜和微波炉策略在四个来源状态获胜，但会误触发。v4 把保险柜、抽屉、冰箱和微波炉归为共同机制。v5 用同一通用程序尝试四类容器。失败前 0/4；原失败反馈之后的零 API 诊断为 4/4，两步获胜。这两个分母分别代表预防与恢复。

v5 把最后一条历史中含无效反馈的 `move ... to ...` 解析成物体与容器实例，依据公开历史估计开闭状态。它没有将失败与当前目标和任务阶段绑定，或确认最新历史中的失败仍有效。当前目标是冰箱或另一个保险柜实例时，仍可能打开旧失败中的保险柜。此外，任一已开容器的合法投递可能绕过失败关联，触发无关动作。验证在失败前调用属于宿主协议时点；收到反馈后仍按旧失败或错误阶段行动属于候选代码。

## v6 单变量任务

复用 v4 已保存的跨容器机制和它引用的 11 条公开分析，仅调用模型生成一份策略。该方案研究固定机制下的策略生成。分析 Prompt、机制来源和之前的正式结果保留。生成契约要求自主实现三项决策，仍使用 `environment_operator(context)`。

- Trigger 检查失败是否与当前尚未完成的任务相关，并确认状态或阶段未使证据失效。
- Binding 核对目标物品、容器实例和任务阶段。
- Recovery 在前两项成立后才选择合法且相关的动作；状态改变后重新核对，证据不足时拒绝。

这三项是分析维度。没有运行时新增的人工修复策略或数学式规则。验收期用冻结 v5 源码作为 Mock 响应回归夹具，观察管线能同时记录其已知成功与误触发。

## 来源与负例

4 局按预先固定的编号 33、40、88、72，从原始无效动作已经发生后的状态开始。验证分支保留原环境回执和同视野内的原历史后缀，执行候选返回的合法动作。短恢复也可通过。最多 12 步或原游戏剩余 50 步。打开正确实例且恢复原本缺失的原投递指令计局部修复；同物同目标投递、环境获胜分别计数。四例必须均有局部修复，所有负例都无误触发和接口错误，才达到本轮开发门槛。整局获胜是独立观察。

负例分三组保存。原 11 个覆盖错误目标、实例、任务阶段及信息不足。两组过时历史各比较无旧记录、旧记录在末尾、其后出现新动作，共六条。新增三条覆盖障碍已解除、子目标已完成、持有物变化。已解除例从空候选状态开始，表示外部已完成恢复步骤，不应抢占正常投递。三组分别报告，存在与旧负例重叠的状态。合成决策结果不估计真实游戏误触发率。

## 可观测诊断

报告候选是否出手、首动作是否打开原失败涉及的实例、是否恢复该投递指令、是否完成同物同目标投递，以及环境 won、拒绝、接口错误和重复动作。重复动作次数是线索，需要结合回执判断是否无进展。Trigger、Binding 和 Recovery 的结论来自这些分开的可观测量；候选 reason 是自报说明，不证明其内部判断正确。机制固定，候选对机制的理解错误只能结合源码和回执进一步审查。失败前预防无 v6 计分分母。
