# B v7 前置审查：B v6 的七次误触发

## 来源及版本

核对 v4 冻结跨容器提案、v5 原始生成源码和失败后回执、v6 原模型源码、工程修订差异和四局逐步回执。v4 提案由 11 条真实公开轨迹支持，涵盖关闭的保险柜、抽屉、冰箱和微波炉。v5 的失败后恢复为 4/4。v6 原始产物在模块顶层调用两次 re.compile，静态拒绝，Worker 0 次。工程修订只将两次调用移入原匹配函数，四个来源均先开正确容器再投递，两步获胜。

源码自末尾回溯首个无效投递，只把同物同容器的后续成功投递视作已解决。读取了 goal 却没有在决策中使用，未检查持有变化、不同实例或任务阶段。随后从当前观察和历史判断容器开闭。关闭分支仅检查旧目标的 open 是否合法，已开分支在同一投递合法时直接接管。Worker 返回理由与这些分支一致。一次 look 可以提供新观察，单靠是否位于末尾不能解决时效问题。
