## 实际动作审查

`s22_action_audit.py`记录输入及输出字符/字节/行数、语法状态、顶层节点、仅定义/导入状态、源码哈希、逐行diff、字符相似度、AST节点类型序列相似度、finish_reason及截断。保留提示分组，不将A直接标为实际局部修复、B直接标为实际算法重建。所有算法改变结论默认 `REQUIRES_MANUAL_REVIEW`，完整算法默认 `NOT_ESTABLISHED`。相似度不作为准入或选优阈值。

10份来源代码字符数依次为45、2175、436、21380、20192、1414、1317、453、594、5588。第一题仅1行；语法可解析不证明程序完成算法。源码长度差异作为描述性分层，不排题、不替题。

真实运行后先对隐去分组和测试结果的源码对进行人工审查：输入输出路径是否完整、原有核心算法/数据结构是否保留、具体修改位置和理由、无法判定的部分。记录审查结论后再关联A/B与评分。不以代码大幅变化自动认定重生成，也不以高AST相似度认定算法相同。另对A与B输出直接比较；共同生成相似程序可能说明提示没有诱导不同策略。单次输出无法证明稳定动作偏好。

## 执行与恢复边界

新增`s22_executor.py`使用原SharedTransport、PersistentBudget和隔离Judge。发送前校验原冻结依赖及新执行器manifest；最终wire必须等于冻结请求。真实模式要求新的Run ID、原协议哈希、新执行器哈希、20次及1美元的明确授权。

独立持久账本不借用旧余额。恢复每个分支原token/工具计数，调用上限只增加1次，分支时钟取原剩余时间与600秒的较小值。实际Worker每次工具调用同时受任务和全局账本约束。未知发送保留预留；不重试。进程锁防止并发发送；INTENT、原始响应、传输审计及评价结果原子持久化。任何未完成分支在重启时停止，不能因已有部分响应就自动重发。已完成Run重启不新增请求。异常恢复可能需要人工核账，这是保守限制，不是自动恢复保证。

`s22_final_review.py`是独立离线入口。全部20分支到达ONLINE_LOCKED后才读取冻结复核数据；核对评分文件哈希和题目身份。中断评分不会自动重复执行。在线入口不读取封存答案；119题确认集与419题长流均未使用。

## 使用

在仓库根目录，使用现有AFlow虚拟环境Python：

```sh
python scripts/s22_executor.py check
python scripts/s22_executor.py mock --run-dir runs/NEW_MOCK_RUN
# 仅在收到新的明确授权并建立匹配授权记录后：
python scripts/s22_executor.py real --run-dir runs/NEW_REAL_RUN --authorization AUTHORIZATION.json
# 在线全部锁定之后，独立离线评分：
python scripts/s22_final_review.py runs/NEW_REAL_RUN
```

本轮不执行后两条真实Run命令。正式发送前仍应复核当前报价与Worker状态；若模型/协议不匹配，应停止而非静默改写冻结wire。

后续20调用仅回答暴露开发检查点上的提示处理效果。公开与严格评分分开报告A-only、B-only、Both-success、Both-fail、UNKNOWN；基础设施未知不可计为模型失败。不能据此宣称实际算法切换、稳定反事实、RQ2可预测性、RQ3历史学习必要性或独立泛化。
