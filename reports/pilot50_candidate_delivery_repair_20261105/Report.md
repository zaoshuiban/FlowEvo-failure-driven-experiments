# DIAGNOSTIC · 候选交付只读回放与修复

T、F 各有一次已收件且有用量记录的候选响应。均使用 DeepSeek JSON object 模式，供应商结束原因为 stop，请求输出上限 8,192 Token。T 和 F 实际输出分别为 1,956 和 1,632 Token。两条原始内容均在零基位置 8 打开 code 字符串，随后保持转义的 Python 内容直到响应结束，外层字符串未闭合。末尾还出现 Python 内部把 code、description 和 applicability 组装成返回字典的痕迹。可观察到的故障是模型把交付封装写进了 Python，外层 JSON 随后无效。没有证据指向达到配置的输出上限，或本地接收器截断内容。

生成提示现在明确要求两项元数据先输出、Python 源码最后，给出实际转义示例，并禁止在 Python 内包装交付字段。接收仍要求完整的原始三字段 JSON，来源、权限、静态及 Worker 验证保持原约束。

收到已计量且完整停止的畸形外层 JSON 时，可在同一作业以一个独立请求槽重新生成。请求依据原冻结规格，记录父响应 SHA。原内容不能可靠恢复，重生结果作为新候选源码处理。该次请求占用已有一次修订额度。第二次交付失败直接拒绝。UNKNOWN、未计量、截断和可解析但契约违规均不能触发此路径。

130 项零 API 组合测试通过。两份原始响应经真实接收器只读回放，均仍被拒绝。随后用模拟响应走有界编译器，第三个请求槽收到可解析封装，但该夹具的语义及源码静态校验仍未通过。原供应商日志字节和旧 Run 成绩保留。未来真实交付率仍待观察，本次付费调用为零。
