# 下一轮失败技能学习决策

结论：`EXISTING_CAPABILITY_SUFFICIENT`。HumanEval/39 这条来源暂不进入强教师新算法获取；新增获取项 **0**，本轮付费请求 **0**。

原程序确实有性能失败，但同一库中的 HumanEval/31 旧实现，经过仅改变绑定的宿主辅助组合后，完成全部原有评分并满足时间限制。因此不能再把本例列为“原系统没有可用素性算法”，也不能把组合成功命名为模型学习产生的新能力。

当前缺的是**已经保存的能力能否被原 Agent 有效发现与使用的证据**。具体应区分检索展示、函数接口绑定、返回值参与计算和整任务通过；本轮只证明宿主组合上界，不证明自主使用。

下一项实验优先研究已有技能自主复用，单独冻结协议后才调用 Actor：保留完整旧 HumanEval G 基础库和既有正确技能，冻结旧 `is_prime` 模块 SHA，不请求 Teacher 改写；对照组与可用绑定组使用逐题相同初始快照和相同正常尝试预算。若需将 legacy 整任务卡接入参数化操作接口，只能标记为接口/准入工作，并保持算法字节身份。不得把本轮人工 B 包装器当作模型产生的独立支持证据或直接绕过激活门槛。

HumanEval/39 可作为已经曝光的训练诊断案例；不能改称未见迁移任务。此前提出的 75、96、72、92 仍只是公开题面候选，未运行、未计作新技能收益，是否用于后续开发任务须按独立性、合法公开样例和固定预算另行冻结。不要自动假定每题都需要素性操作。这里不附强教师预算，因为新算法获取的前提已经被本轮结果否定。

对于失败技能学习研究：

1. **当前是否确认缺少新算法？** 本例没有；不排除系统存在别的缺口。
2. **预期学习什么新操作？** 本例没有待获取的新操作。先复用已有整数素性判断，不重复学习相同职责。
3. **没有新缺口是因为已有能力还是证据不足？** 已有能力在一次有效、可比的完整任务评分中足够；自主使用能力仍证据不足。B 的有效重复只有一次，这一限制保留。
4. **重复有效性还需多少种机制？** 先找到 **1 种**确实未被现有库满足的真实缺口，就可以开始有界学习，不等数量凑齐。若第一条链有来源恢复与新任务复用证据，再增加至少 **2 种不同机制**作为跨机制开发复现的起点；合计 3 种是研究规划起点，不是统计充分性保证。本次素性组合不算其中的新算法获取成功。

不继续优化 HumanEval/39，不增加相似输入或反复修订素数程序。新算法学习应转向其他独立、可信、具有复用价值的缺口；既有能力的发现/绑定问题单独保留在复用研究目录中。
