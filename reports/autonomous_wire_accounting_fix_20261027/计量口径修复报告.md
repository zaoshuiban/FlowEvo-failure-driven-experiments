# 编译器最终请求计量口径修复

结论：零 API 验收通过。原真实 Run 的停止结论、响应、协议和账本未修改，未续跑模型。

## 改动

`BoundedCompiler.request` 对具有 `preflight/prepare` 接口的生成器，统一使用最终 canonical JSON 的 UTF-8 字节数加256作为保守输入上界，预检、预算预留和 `WIRE_PREFLIGHT` 日志使用同一个值。日志新增 `input_accounting=final-wire-utf8-plus-256-v1`。不再取内部 request 的 repr+4096 与实际 wire 的最大值。

没有最终wire接口的旧生成器仍保留原估计，避免在无法检查真实请求时削减保护。原32768上限、输出上限、货币预留、严格输出契约和安全权限未放宽。新Pilot准备入口也采用同一最终wire公式。旧Run源码哈希因此不再匹配当前实现，这是预期的版本边界；旧Run不可直接重跑，新真实执行须另行冻结。

这里的字节加余量是原系统的保守输入估计，不是实际分词结果。实际消耗继续依据供应商返回usage记录。
