## 原生行为及新入口对应关系

| 文件 | 原生行为 | 接入结论 |
| --- | --- | --- |
| run_20task_validation.py | 每题前 advance_episode、retrieve；当 L2 或 L3 可用时按种子 1337 抽取 20% 引导 holdout，保留 L1；用实际路由记录 ContrastiveEval；成功后编译；每 20 局审计。原 resume 对 RNG 仅作近似恢复。 | 沿用其常量和同样调用顺序，持久保存在线 RNG 和治理状态。v2 锁库评价关闭随机 holdout，照常检索治理允许的技能。 |
| compiler.py | 成功且有动作时产生 L1 参数化动作模板及 L2 指南。L1 来自原版任务蓝图，L2 用成功动作轨迹生成最多五条规则，模型上限 500 Token。模型异常时原版可采用规则 fallback。 | 直接复用编译器；为 500 Token 请求配置独立通道和 ID 前缀，与求解共用账本。真实传输或交付异常即使被编译器捕获也阻止提交该次更新，防止工程缺失污染学得的库。 |
| skill_library.py | 存储、检索、淘汰、审计。L3 至少三个样本后聚合历史统计，成功轨迹贡献拾取位置频率，普通失败贡献超时、循环等 common_pitfalls。治理可压制 L2/L3 注入，并独立审核 L1 效用。 | 同一个 SkillLibrary 和原有阈值。正常失败继续进入 L3；截断、UNKNOWN 和基础设施异常不进入轨迹统计。未来 F 的增量是结构化失败修复策略，G 已有失败统计。 |
| executor.py / param_extractor.py | L1 可绑定时执行直接模板；失败后以最新观察回退。L2 每步进入用户提示，L3 进入系统指令。双物体由入口跳过 L1 绑定，executor 也设有该类型的直接执行限制。 | 复用原生代码和绑定限制。日志区分检索、绑定、直接动作、逐请求注入、回退、治理抑制及最终 won。L1 生成或被检索均不等于在双物体局实际执行。 |
| generator.py | 动作生成和解析由原生实现负责，旧默认输出 256。 | 保持提示和解析行为，用现有 GenerationSettings 参数设置 1024；现有 DeepSeek wire 使用 temperature 0、thinking disabled。 |
| env.py | 默认验证模式遍历库；旧 train 配置递归扫描整个 json_2.1.1。done 可能只是 TimeLimit，成功取 won。 | 新入口限定真实 train 子树，逐局以冻结单游戏重置并核验路径。使用 TextWorld 的无专家请求包装和相同的 50 步上限，避免向客户端提供 expert_plan。环境回执与最终 trace 的 won 和步数交叉核对。 |

旧治理的 holdout 只遮蔽提示注入，因此可能保留直接技能。原入口在 holdout 时按原逻辑记 unguided，并按实际 planning_mode 记 guided；本次保留这个口径。它不等同于在所有类型上对所有技能做随机开关，尤其存在 L1 的类型。双物体没有直接绑定，所以该类 holdout 的确屏蔽 L2/L3。v2 正式评价既不写回治理计数，也不消耗 holdout RNG。已被原生治理压制的技能仍被遮蔽。这是相对原版在线流及 v1 锁库设计的协议改动，未来 G/F/R 的锁库阶段必须共享。

## 兼容实现和边界

- 新增 `FlowEvo/src/alfworld_/success_baseline.py` 作为适配器，复用现有执行器、生成器、编译器、库、审计客户端和费用账本，保留原版文件及旧 Run。
- 新增 `scripts/run_alfworld_success_baseline.py` 作为独立 G 入口，冻结真实数据路径、样本、依赖、代码哈希、资源、校准和正式授权身份。没有接入任何结构化失败生成器或失败 Registry。
- 每局有环境步骤回执、锁定结果、编译日志和一次原子式题间提交。恢复时校验公开状态、wire 哈希及已结算用量，UNKNOWN 或不可验证的漂移阻断。
- 真实环境上的历史回放证明双物体任务的 L2/L3 内容确实送达后续动作请求。脚本动作取自既有成功轨迹，因此该测试无法估计提示改变动作或成功率的因果效果。
- 依据本地已存档的实验与工程协议排除历史游戏和场景。无法核验外部或未归档曝光，也无法判断预训练曝光。正式比较必须使用同一冻结任务顺序、基础设置及成功学习路径。若另设动态对照，需在相同 120 局独立重跑。

## 双物体研究范围

历史动态 G 的 18/20 是小样本，只有 2 局失败，完整成功学习版在该类型的真实成功率仍未知。若动态失败率 10% 在同一分布稳定，旧 90 局双物体在线设计只期望 9 局失败，新混合在线流的 41 局双物体只期望约 4 局。可诊断且能重放的机会还会更少；这些数值只用于规划，不能作为真实机会率。16 局校准保留原双物体样本，适合核验指南、状态提示和异常恢复。该类型是完整 full_library 实现中的受限路由，实证上主要衡量 L2/L3 与未来失败恢复策略的结合。混合正式流可以观察原版 L1 在其他题型的直接执行及回退，仍需实际记录其发生次数。

## 与原版的差异分类

- **持久化与安全。** 共享预算、动作/编译不同请求身份、回执绑定、公开环境前缀核验、won 判定和 UNKNOWN 阻断属于兼容保障。原版遇编译传输异常可转规则 fallback，新入口保留原生编译器，但在已捕获的传输/交付异常时拒绝提交。本规则改变异常样本的处理。正常完成的编译和 executor 路由不变。
- **数据及试验控制。** 严格 train 路径、逐局固定重置、去专家包装、场景隔离、固定 DeepSeek wire、1024 输出上限、锁库和评价关闭 holdout 都属于本地协议差异，可能改变观测成绩。在线成功编译、原生 L3 失败统计、治理阈值、动作模板、参数绑定及回退规则沿用原实现。
- **估计对象。** 在线阶段测持续积累并保留原生治理 holdout；评价阶段测已冻结库的正常部署表现。两阶段结果单列，不能用两段成功率之差估计取消 holdout 或学习的因果效果。没有启动任何新增失败策略。

结论是本地 G 已达到零 API 工程基线条件。后续 F 的可信实证比较仍需小规模真实校准及正式 G 结果，不能以 Mock 通过代替。
