## 请求上界及异常

6,090 由 120×50 动作请求和最多 90 次在线 L2 编译组成。每步至多一次动作生成，L1 直接动作占同一 50 步配额，回退只用剩余步数。每个合格在线成功至多触发一次 500 Token 编译。L1、L3、检索、治理、重放已结算响应和锁库阶段都没有额外编译请求。812 按 16×50＋12 同理。连接恢复发生在可证明的发送前边界，不追加已发送的请求。预检拒绝或预算不足停在发送前，UNKNOWN 阻断并保留预留，截断已计量但不会提交成功。代码没有额外真实重跑、反事实调用或模型评审；若将来加入，应另冻预算。

## 试验行为与校准判据

- G 从空库开始。在线局仅在结果锁定后更新库和治理。第 12/90 局提交后、首个评价局开始前冻结库、治理和在线 RNG。在线阶段保留原版 20% holdout；锁库评价禁止随机遮蔽，始终提供治理允许且匹配当前状态的技能。评价不消耗 RNG、不更新库或治理。未来 G/F/R 采用同一设置。对这套学习后的库单列评价成功率，在线分母和全程分母分别报告。
- 校准第 6 局后暂停，恢复到下一局。核对两类请求 ID、发送和结算计数、Token、金额和恢复前后库哈希。真实 API 异常单列，若不能核验则暂停。
- 校准逐局绑定「成功轨迹 → L2 源指南 → 目标局请求 → 响应动作 → 环境转移」。源指南需与真实成功步骤一致、可执行、有明确适用条件，避免记住源对象编号或当前目标实例。仅生成文本、仅被检索、请求已收到指南、动作层使用证据分别计数。
- 对所有实际 L2 送达局做动作级复核。用指南条款、响应中的对应理由（若有）、当时合法动作和随后反馈，分类为 `DELIVERED_ONLY`、`BEHAVIORAL_UPTAKE`、`CONTRADICTED_OR_HARM`、`INDETERMINATE`。普通且本来也会做的动作不能单独计为使用证据；至少要能指出指南要求的具体选择与观测及实际转移的对应。错误检查包括错误对象、错误顺序、循环和已完成子目标被破坏。理由与行为一致支持采用判断，因果改变仍需独立同检查点开关对照。此轮使用已有回执人工核查，费用上限不含额外模型判定。
- **校准启动准入**为工程和数据预检通过、待单独授权 $11。**校准通过**需要真实可用指南、跨局送达、至少一个可复核行为采用案例，以及真实计量和恢复链一致；还应记录一次不可用/holdout 或抑制实例。若明显有害、没有明确使用证据或恢复/计量异常，记录部分通过或失败并暂缓正式申请。无需显著正确率提升。
- 正式启动需要校准报告及单独授权。CLI 的硬检查仅覆盖校准完成、协议绑定、已观察到 L2 送达和暂停回执，不能自动判断指南质量、真实使用或伤害。正式申请时须另以校准报告判断。
- UNKNOWN、响应截断、无法复现的环境前缀及预算阻断均保留独立停机原因。STOP 是曾中断的诊断记录，最终结果与覆盖率以已提交题间链和 summary 为准。部分运行的未提交局不填成环境失败。


## 账本与指标

每局保存 `episodes/<task_id>/environment.jsonl`、`locked.json`、动作与编译两套 `requests.jsonl`。根目录 `episodes.jsonl` 绑定顺序、路由、实际注入、治理、生成和库快照，`frozen_bank.json` 绑定冻结评价库，`budget.jsonl` 记录预约、结算与停机。通过这些回执分别报告全程、在线、锁库的成功率、步数、每局 Token 和全部费用，以及累计成功率、各层生成/入库/检索/实际应用、库大小、抑制、回退和异常。L2/L3 内容出现在已结算请求中计作注入，动作或成功率的增量需要同题对照。未取得供应商账单时将费用估计和预留分开列示。
